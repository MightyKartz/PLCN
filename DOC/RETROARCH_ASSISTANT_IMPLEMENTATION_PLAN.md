# RetroArch 助手：游戏库、多盘管理与存储优化实施方案

- 编写日期：2026-11-15
- 项目：PLCN
- 文档状态：后续实施方案；本文不代表新增功能已经实现，也不授权立即转换或删除掌机文件。
- 目标：让用户选择设备与游戏目录后，完成扫描、名称与图片匹配、多盘管理及空间优化，并能理解、核对和恢复每次修改。

## 1. 产品定位与已有基础

产品定位建议升级为“RetroArch 助手”，保留 PLCN 项目名称，品牌改名可独立决定。

现有基础包括设备选择、本机与存储卡目录浏览、增量更新 Playlist、核心推荐及官方下载安装引导、中文名称与图片补全。近期已针对缩写、盘号及路径自动恢复修复若干具体问题。

后续需要把这些能力整合为统一工作流，并新增游戏分组、M3U 管理和存储优化。实现开始前应核对当前代码与真机行为，不能把既有个别游戏的修复等同于通用识别能力已经完成。

### 产品原则

1. 首页选择物理设备，同一掌机的本机和存储卡合并展示。
2. 目录选择后由程序恢复主机、核心与启动路径；不能确定时才要求选择或补充。
3. 游戏库以“一款游戏”为展示单位，光盘和音轨是游戏的组成文件。
4. 扫描与预览只读；文件、列表和备份的修改在用户确认具体方案后执行。
5. 一次任务提供一份可核对的方案，避免逐项弹窗和重复确认。
6. 原文件清理必须建立在目标校验、引用更新和备份核对成功的基础上。

## 2. 信息架构与主界面

### 2.1 首页：选择设备

显示设备名称、连接状态与存储空间数量，主操作为“进入设备”。保留重新检测。不要在首页要求用户决定创建列表、扫描、压缩或整理目录。

进入设备后，分别显示：

- 游戏所在存储与目录，例如“Games / Roms / SS”。
- 列表保存位置，例如“内部共享存储空间 / RetroArch”。

二者允许属于同一掌机的不同存储。MTP URI 与 Android 启动路径在内部单独保存，不用 MTP 存储编号猜测 Android 存储卡挂载路径。

### 2.2 主导航

| 页面 | 主要职责 | 主要操作 |
| --- | --- | --- |
| 游戏库 | 浏览游戏、扫描新增、名称图片补全、多盘详情 | 更新游戏库、补全名称与图片 |
| 存储优化 | 空间分析、CHD 转换、按主机整理目录 | 分析空间、预览优化方案 |
| 任务与恢复 | 任务进度、结果、失败重试、备份与恢复 | 查看结果、继续任务、恢复 |

主机筛选仍放在游戏库左侧。设备与存储信息集中在同一位置，避免多个页面分别维护设备选中状态。

### 2.3 游戏列表与详情

多盘游戏示例：

```text
[封面] 空想科学世界
       Saturn · 2 张光盘 · CHD · 已配置多盘入口
       [查看光盘] [更换图片] [更多]
```

默认只显示一个游戏入口。详情展开后显示每盘的盘号、顺序、实际文件路径、格式和体积，以及 M3U 的位置。

统计区分“游戏数”“光盘数”“文件数”；完成多盘合并后，光盘文件不会因为游戏入口变少而被删除。

## 3. 扫描、匹配与更新流程

流程：选择目录 → 自动识别配置 → 开始扫描 → 预览变更 → 确认更新 → 查看结果。

### 3.1 配置自动恢复

- 依据已保存的精确扫描配置、现有列表及目录中的游戏信息识别主机和启动目录。
- 唯一匹配时自动填入；多个合理候选时让用户选择，不能把第一个候选当成已确认身份。
- 目录选择器打开时，“开始扫描”采用当前已加载目录，并等待识别完成；读取中禁止使用未完成的目录结果。
- 路径、主机、核心、存储切换后，旧扫描方案立即失效。旧异步响应不能回填新配置。
- 核心按兼容性、设备性能和实际格式需求推荐，允许更换。不能为追求压缩自动更换用户已有核心。
- 核心状态区分“已确认安装”“安装状态未知”“需要安装”；下载、传输及填写核心路径都不等于安装成功。
- 新装 RetroArch 没有列表时，不能依赖旧列表完成全部识别；须为无法发现的存储映射或核心安装信息提供清楚的引导。

主机、扩展名、完整启动路径与核心路径放进“扫描设置／高级设置”。正常流程主要展示识别结果及需要用户处理的问题。

### 3.2 统一预览

预览应汇总：新增游戏、保留游戏、名称修正、图片补全、多盘分组、路径变化及待处理问题。

说明每个方案的范围，例如“只补图片”“新增 5 款游戏”“将 2 个分盘入口改为 1 个多盘入口”。一次确认应用所选方案；结果显示成功、跳过、待补充和失败，不把任务结束等同于全部成功。

匹配逻辑区分精确名称、校验值、已确认人工规则和模糊候选。中文译名匹配成功不自动证明地区、修订和盘号；模糊候选不能升级为确定身份。

图片状态使用“已有图片”“可补全”“待选择版本”“未匹配图片源”“图库查询失败”。未匹配名称时，不宣称官方图库缺图。

## 4. 多盘与 M3U 管理

### 4.1 文件结构

推荐每个主机一个目录，独立游戏文件平铺。例如：

```text
Roms/
├── SS/
│   ├── 仙窟活龙大战.chd
│   ├── 空想科学世界.m3u
│   ├── GulliverBoy Disc1.chd
│   └── GulliverBoy Disc2.chd
└── PS1/
```

上述 M3U 的 UTF-8 文本内容为：

```text
GulliverBoy Disc1.chd
GulliverBoy Disc2.chd
```

使用相对于 M3U 所在位置的路径，每行一个文件，顺序对应换盘顺序，不添加引号。CUE＋BIN 游戏引用 CUE，不引用单独 BIN 音轨。M3U 只组织引用，不包含或压缩光盘数据。

### 4.2 分组规则

- 结合平台、标准游戏身份、版本信息、盘号和目录上下文分组，不能仅凭同名中文标签或相似文件名合并。
- 统一识别 `(Disc 1)`、`Disc1`、`Disc 1` 等明确盘号形式；保留原始名称与识别证据。
- 明确区分顺序换盘、附赠盘、试玩盘和同系列不同作品。无法确认关系时列为待核对。
- 支持检查缺盘、重复盘号、失效引用、混合地区和不同汉化版本；允许调整顺序或拆分错误分组。
- 既有 M3U 优先读入，不重复生成同一组入口。
- 生成 M3U 后，列表指向 M3U，移除的只是其覆盖的重复分盘入口，保留磁盘文件及不属于本组的列表条目。
- 不同列表对同一文件的引用必须一并检查，不能只更新当前屏幕上的列表。

### 4.3 存档与图片

改为 M3U 启动可能改变核心使用的存档名称。迁移前识别当前核心及存档设置，备份后再提出复制或映射方案；无法可靠定位时显示待处理。不要默认即时存档跨格式、路径或核心兼容。

游戏组可以展示一张主封面；分盘详情保留各自图片源。不要把不同盘的图片写到同一目标文件名而相互覆盖。

## 5. 存储优化与目录整理

### 5.1 第一版范围

优先支持 Saturn、PS1 的受支持光盘镜像转 CHD。建立“核心＋版本信息＋输入格式＋目标格式”的能力规则；未知支持状态时禁止自动替换，不能只按主机名判断。

CHD 使用官方 MAME `chdman`，记录工具版本与来源。具体输入格式、压缩参数、分发许可证和打包方式需在本阶段开始时核对。

普通卡带 ROM 的 ZIP 压缩和其他平台格式放到后续阶段。街机 ROM 集首版跳过，避免破坏集合结构与校验关系；已有压缩文件默认跳过。

### 5.2 空间分析页面

每款游戏显示当前格式、当前体积、目标格式、核心支持状态、转换条件和问题。节省空间的数值标明“估算”或“实际”，不承诺统一压缩比例。

同时检查电脑工作目录空间及掌机目标空间，计算原文件、转换输出、上传暂存和备份所需空间。源文件有多个引用时，空间统计去重。

执行选项：

| 选项 | 行为 |
| --- | --- |
| 仅转换，保留原文件 | 输出校验后的压缩文件，明确是否切换启动入口；源文件保留 |
| 转换并替换，保留电脑备份 | 核对备份和目标，更新引用成功后清理方案内的源文件 |

预览必须明确列表是否切换、原文件是否清理、备份位置及恢复范围。首轮真机试用先采用“仅转换”，验证运行和存档后再开放对应游戏的替换流程。

### 5.3 转换任务顺序

1. 固定用户确认的游戏、源文件集合、目标位置、引用变化和备份方案。
2. 通过 MTP 把文件读到电脑，检查源文件是否与方案一致。
3. 在电脑执行转换；一份 CUE 及其全部音轨作为完整光盘处理。
4. 验证 CHD 完整性。完整性校验不等于与原始音轨内容完全等价，转换验证还需建立源与输出的内容核对方法。
5. 上传到目标存储，回读并核对传输结果。
6. 备份并更新受影响的 Playlist、M3U 等引用，回读核对。
7. 替换模式下确认电脑备份完整，再清理方案内且不再被其他内容依赖的原文件。
8. 记录实际空间变化和结果。文件校验通过与真机运行验证使用不同状态。

CUE、BIN、CHD 之间存在依赖关系；多个 CUE 共用音轨时，不能仅因一个入口转换完成就删除共享文件。首版只自动处理能够完整确定引用范围的文件集合。

### 5.4 按主机整理目录

作为存储优化的附加选项提供，不在扫描后自动移动文件。

- 可独立运行的 CHD 和卡带 ROM 放进主机目录。
- 多盘文件平铺，并生成或更新 M3U。
- 未转换的 CUE＋BIN 及其他多文件依赖游戏保留子目录。
- 首次整理优先沿用原文件名，中文译名主要用于列表展示。
- 同名冲突进入预览；不能覆盖已有文件，也不能用中文名相同作为重复游戏的判断依据。
- 移动后同步维护相关路径与引用，核对存档定位。
- 独立游戏不强行变成单文件；明确保留特殊格式例外。

## 6. 数据与任务契约

以下为逻辑模型，实施时可映射到现有结构，不要求立刻重写全部存储。

| 对象 | 需要保存的信息 |
| --- | --- |
| Device | 物理设备身份、连接方式、各存储空间及连接状态 |
| Library | 目标列表位置、图片目录、来源目录、已确认的 Android 路径映射 |
| Game | 稳定游戏标识、平台、显示名称、身份依据、核心关联、主启动入口 |
| Disc | 所属游戏、盘号、角色、地区／修订、内容文件引用 |
| ContentFile | 实际路径、设备与存储、格式、体积、校验记录、依赖关系 |
| ChangePlan | 只读分析结果、源文件版本、待修改引用、冲突、备份和删除范围 |
| Operation | 已确认方案、当前阶段、逐文件结果、备份与可恢复状态 |

稳定标识不应只取中文名称或当前路径；改名、移动、转换后仍需关联原游戏和图片选择。具体标识生成及既有数据迁移在第一阶段确定。

执行端使用服务端保存的方案；应用前检查相关源文件是否变化。设备、目录、主机或选项变化后，客户端使方案失效。校验与备份记录写入任务清单，以便中断后明确哪些阶段完成。

MTP 多文件更新不能视为原子事务。中断时保留已完成阶段和真实结果；继续任务前核对已上传文件及引用，避免重复转换、重复删除或把部分完成误报成功。

## 7. 实施阶段与验收

### 阶段一：统一身份、配置与状态

交付：游戏／光盘／内容文件的基础模型，扫描配置自动恢复，统一变更预览，核心与路径状态。

验收：

- 同一设备双存储可用，ROM 来源与列表位置独立。
- 目录选择、主机切换及旧请求回填不会污染当前配置。
- 能从旧列表恢复路径，也能解释新装 RetroArch 的未知配置。
- 精确身份、模糊候选、图片查询失败和缺少图片源有不同状态。
- 已有人工核心设置、中文名和图片选择能够保留；明确纠错规则有证据可查。

### 阶段二：游戏分组与 M3U

交付：游戏组列表、多盘详情、盘序编辑、M3U 预览和应用、存档衔接检查。

验收：

- 用“空想科学世界”两张盘验证简称与盘号映射、唯一游戏入口和各盘图片源。
- 用三盘、缺盘、重复盘号、附赠盘和不同版本样例验证分组边界。
- CHD 和 CUE 两类入口生成的 M3U 可被受支持核心加载；真机验证换盘。
- 已有 M3U 重复扫描不重复导入；预览不写文件。
- 修改后可恢复列表、M3U 和受影响的存档文件。

### 阶段三：CHD 转换

交付：空间分析、能力检查、电脑转换、校验、MTP 回传、备份及恢复。

验收：

- 单盘、多音轨、多盘、汉化镜像及中文路径测试通过。
- 核对目标核心实际支持的格式，真机验证运行和存档。
- 目标冲突、空间不足、取消、传输中断和校验失败时，源文件与启动引用仍可恢复。
- 源音轨共享和跨列表引用被识别，未满足清理条件时不删除。
- 有电脑备份且目标与引用校验完成后，替换模式才可清理源文件。
- 实际节省空间与清单中的文件变更一致。

### 阶段四：目录整理与更多格式

交付：按主机整理、重名冲突处理、引用联动，以及经过核对的卡带 ROM 压缩支持。

验收：主机目录平铺目标达成，多文件例外保留；跨目录引用、存档和图片关联经验证；恢复能够还原原目录关系。

## 8. 工程落点与实施边界

开始实施时检查以下模块，尽量复用已有能力：

- 扫描与引用：[content_scan.py](../src/content_scan.py)、[rom_paths.py](../src/rom_paths.py)。
- 名称与图片身份：[playlist_analysis.py](../src/playlist_analysis.py)、[artwork_identity.py](../src/artwork_identity.py)、[saturn_artwork.py](../src/saturn_artwork.py)。
- 设备传输：[mtp_runtime.py](../src/mtp_runtime.py)、[playlist_transport.py](../src/playlist_transport.py)。MTP 读取和写入继续由服务进程统一管理。
- 界面：[plcn.html](../src/templates/plcn.html)、[content-scan.js](../src/templates/content-scan.js)、[library.js](../src/templates/library.js)。
- 转换、文件引用分析和优化任务可新增独立模块，避免把大文件处理塞进名称匹配模块。

首版边界：Android 文件传输及本地文件为主要验证对象；不要求开启 USB 调试，不以自动安装核心、下载 BIOS、升级全部核心或支持所有压缩格式为先决条件。批量替换真实游戏文件应在阶段验收通过后，通过具体优化方案执行。
