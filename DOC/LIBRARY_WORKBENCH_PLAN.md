# 游戏库工作台实施计划

设计基准：[已选概念图](design/library-workbench-concept.png)。保留真实游戏库、原有修复与工具功能，概念图任务数字与封面不作为静态业务数据。

## 1. 页面结构与导航
- [x] 单侧栏：品牌、游戏库、扫描与导入、任务中心、主机分类、工具与设置。
- [x] 紧凑设备栏：连接状态、存储范围、设备详情；原始路径移入详情。
- [x] 工具菜单保留 CHD 转换、目录整理、ROM 压缩入口。

## 2. 游戏库首页
- [x] 去掉欢迎大卡，改为真实游戏/主机数量、资料分析状态摘要。
- [x] 主操作“扫描新增游戏”、次操作“补全名称与封面”、独立“手动添加”。
- [x] 主机卡片使用实际游戏库封面，支持搜索、网格/列表切换与进入主机。
- [x] 按实际数据展示存储位置，未统计状态不显示虚构零值或就绪状态。

## 3. 扫描与存储
- [x] 自动扫描入口与现有手动目录导入分离；扫描不立即写入掌机。
- [x] 自动发现支持主机目录，汇总新增/已有/待配置结果，确认后增量生成列表。
- [x] 共用 BIOS 过滤、多盘入口及已有条目保留规则；保留手动名称和核心设置。
- [x] 存储筛选显示实际来源；跨存储路径未确定时不生成不可启动的路径。

## 4. 任务与状态
- [x] 底部任务栏显示真实运行进度、状态和查看详情入口。
- [x] 不展示未实现的暂停；保留后端实际支持的取消操作与失败详情。
- [x] 运行任务不会把首页替换成空白；刷新与返回后的状态一致。

## 5. 验收与交付
- [x] JS 语法、状态单测与 Python 回归检查。
- [x] 真实浏览器验证首页、搜索/主机导航、扫描/手动添加、工具、任务入口。
- [x] 大屏与窄窗口截图，比较概念图，修复截断、遮挡和布局溢出。
- [x] 本机服务加载修改，记录截图和实施边界，提交变更。

## 实现约束
使用现有 HTML/CSS/原生 JS，不迁移框架。封面来自现有缩略图；空库展示可理解的空状态。蓝色突出主操作，暗色中性背景、细边框、清晰键盘焦点；保留浅色主题和中英文切换。新扫描结果必须先汇总再写入，不自动安装核心或更改 ROM 文件。

## 本次实现与验收记录

- 页面：`src/templates/workbench.js`、`workbench.css` 与现有模板；沿用原有列表、修复和工具功能。
- 数据：`workbench_library.py` 提供实际封面、每类存储游戏数量和缺图状态；统计未完成时不显示假就绪。
- 导入：`automatic_scan.py` 与 `/api/content/auto-preview`、`auto-apply`；常见 Roms/Games 容器与十种已支持主机目录，支持跨选定存储汇总。
- 扫描不对混合 ROM 目录猜测平台、不下载整个 ROM 做校验；未确认 Android 启动路径的目录列为待配置。未配置核心使用 RetroArch 的 DETECT，已有核心与条目字段保留。
- 存储筛选用于浏览。补全操作沿用现有列表流程，筛选时按钮明确“整个列表/全部存储”的实际作用范围。
- 任务：轻量 `/api/jobs/status`，真实进度、取消和详情；自动扫描对话框内也可取消。沿用已有上下文写入锁定，任务期间首页仍可查看和搜索。
- 浏览器：1400×900 桌面、780×900 紧凑窗口；已验证搜索、存储空状态、网格/列表切换、主机列表、手动添加、自动扫描预览→确认导入→再次扫描无重复。
- 数据验收使用掌机缓存的 612 个游戏、10 台主机的本地副本；导入验收仅添加一个明确标记的临时测试文件。没有在掌机应用扫描或修复。
- 验证：完整 Python 回归 530 项通过（含两种浏览器视口）；新增取消保留数据测试与相关安全检查 18 项通过；Node 状态测试 130 项通过；JS 语法检查通过。
