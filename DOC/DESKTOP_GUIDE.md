# PLCN 桌面预览版使用与发布

本轮是 v3.2 桌面体验预览，尚未发布正式版本。桌面基础 PR：[MightyKartz/PLCN#5](https://github.com/MightyKartz/PLCN/pull/5)，UI 精简 PR：[MightyKartz/PLCN#6](https://github.com/MightyKartz/PLCN/pull/6)。

## 普通用户

Windows：安装 `PLCN-Windows-x64-Setup.exe` 后，从开始菜单启动；也可以解压便携 ZIP 后双击 `PLCN/PLCN.exe`。便携包默认仍使用用户数据目录，程序升级不会覆盖配置。

macOS：选择对应架构的 `PLCN-macOS-arm64.dmg`（Apple Silicon）或 `PLCN-macOS-x64.dmg`（Intel），将 PLCN.app 拖到 Applications。当前 CI 产物为未签名/未公证预览，不能作为正式分发就绪的声明；发布者应完成下方签名验收。

打开后出现浏览器工作台，关闭标签不停止服务。再次启动会打开已有服务，不创建第二个实例。需要停止时用右上角“工具 → 退出”，有运行任务时会提示先等待或取消。

1. 点击“选择游戏目录”，选择 RetroArch、SD 卡或挂载目录；程序识别列表和图片目录。也可使用“自动检测”，或通过“手动选择文件或路径”直接指定列表。扫描完成后，在左侧选择主机或具体列表，右侧立即显示当前名称、ROM 文件名和已有图片，支持搜索；同一主机的多个列表会分别展示，可逐个切换。浏览只读取列表和现有图片，不执行名称匹配或写回；图片目录未设置时可在“路径设置”中指定。
2. 选择本次操作：修复名称并补图、仅修复名称、仅补全图片。仅补图按原 label 保存图片，不重写 `.lpl`。
3. 点击“预览变更”。默认显示带数量的“全部 / 待确认 / 可应用”，其他条件在“筛选”中展开。核对后点击“应用 N 项变更”，查看摘要并确认；点击“全部”不会改变勾选。风险条目仍须逐项核对；界面的匹配说明以证据与冲突为主，不把规则评分当成准确率。
4. “任务与恢复 → 任务”显示本次运行的进度和错误；可以取消、重试未完成的本地图片。取消在安全边界生效，已写回的名称、已下载的图片会保留。当前网络请求/数据包构建结束前可能仍显示运行中。
5. “任务与恢复 → 恢复历史”列出最近 100 条本地列表写回记录。恢复前检查列表与备份的摘要，列表被其它程序修改则拒绝覆盖；同时保留恢复前备份。图片不会随列表恢复删除。ADB 备份仍在设备上，当前需手动恢复。

更换目录、手动修改路径或切换操作类型后，旧预览会清除。运行期间输入和应用操作锁定；进度连接断开时保留锁定并自动重连，避免重复提交。再次启动可使用“继续上次目录”，不会自动扫描未连接的设备。

左侧主机导航显示每个主机的游戏数量，支持搜索；同一主机有多个列表时展开具体列表，单列表不重复显示卡片。目录操作在“管理”中。游戏区顶部提供搜索及“全部 / 缺图 / 需检查”筛选，整份列表的修复入口收在“批量整理”中，修复步骤只在预览与应用阶段显示。压缩包路径如 `中文名.zip#Bikkuriman World (Japan).pce` 在 ROM 列只显示内部文件名，悬停可查看完整路径；英文名识别也使用同一内部文件名，实际 ROM 路径保持原样。

### 只更新一个游戏的图片

在当前游戏列表中，点击该行的“补图”或“更换图片”，程序先识别英文名并自动搜索 RetroArch / Libretro 官方图库。优先复用上次确认的图片源，再查询当前主机的名称库和 ROM 文件名；名称存在歧义时先选择游戏名称。自动搜索限定同一游戏，并将完整名称匹配放在前面，保留地区版本供核对。找不到名称、图库没有图片和网络失败会分别提示。

候选以图片卡片展示，选择后并排查看当前图片和候选图片，确认后才写入。可以修改英文名搜索，或导入 PNG、JPEG、WebP 本地图片（最多 12 MiB）；搜索期间本地导入始终可用。成功确认的在线图片源保存在用户数据目录的 `artwork-sources.json`，按游戏和图片类型复用，不改变名称数据库或游戏名称。

核对候选图片和保存位置后，点击“确认”。此操作只更新当前游戏所选类型的一张图片，不改名称或 `.lpl`，支持本地目录和 ADB 设备。替换时在原图旁保留 `.bak-…` 备份，校验成功后自动关闭弹窗、回到该游戏行并显示新图和结果；将指针停留在备份提示上可查看备份路径。缺失、损坏和读取失败分别提示。传输失败时保留弹窗供重试，任务状态暂时失联时“查询更新结果”会继续查询原任务。

图片按当前列表名称保存，预览后列表或目标图片发生变化会拒绝写入，需要重新预览。两个条目共用同一图片文件名时，不允许通过单游戏操作覆盖共享图片。图片备份暂需手动恢复。

系统文件选择器运行于独立 helper 的主线程；不可用时自动回退内置文件浏览。原生选择器的真实桌面交互仍在人工验收清单中。

## 数据库更新

右上角“工具 → 名称数据库”提供检查上游版本、下载并比较、比较已安装包、启用和回滚。在同一面板查看新增、移除、译名变化和未翻译数量后再启用；这些数量不是准确率评估。切换会清除旧预览，人工规则保留。首次数据导入可能需要等待几秒，之后使用缓存。

数据包在应用数据目录的 `packs/`；比较普通 CSV 时创建可复用的 baseline 快照。更新包不自动启用。启动时不会自动联网更新名称数据；DAT 未缓存时仍沿用现有按需下载行为。失败图片重试不会再次改名；命名冲突和 ADB 推送不在此重试入口中，需修正后重新预览。

## 数据存储与迁移

| 内容 | Windows | macOS |
| --- | --- | --- |
| 配置、规则、数据包、历史、日志 | `%LOCALAPPDATA%\PLCN` | `~/Library/Application Support/PLCN` |
| 可重建缓存、DAT | `%LOCALAPPDATA%\PLCN\cache` | `~/Library/Caches/PLCN` |

Linux 使用 XDG 用户数据/缓存目录。`PLCN_HOME` 可显式指定独立数据目录，用于便携场景和测试；设置后缓存也放在该目录下。它应为可写、仅当前用户使用的目录。

首次启动复制已知旧程序目录中的 `config.json` 与人工规则，不删除原件；将旧相对路径转换为绝对路径，失效的内置数据路径改回资源默认值。已有新配置不覆盖。迁移记录为 `migration.json`，桌面日志为 `logs/desktop.log`，超过 5 MiB 时在下次启动轮换。之前自行移动程序、把配置放在其它目录的情况，需从高级设置重新选择路径或手动迁移。

源文件与内置名称数据只读使用；运行时不再依赖安装目录可写。旧根目录 `plcn.db` 仍不改动，缓存可从 CSV 重建。原始列表和相邻备份仍留在用户游戏库。

## 从源码与本地打包

```powershell
# Windows，项目根目录
.\venv\Scripts\python.exe src\plcn.py ui
# 无控制台入口（系统的 pythonw 或虚拟环境 pythonw）
.\venv\Scripts\pythonw.exe src\desktop.py

# 测试与 JS 检查需要 Node.js（CI 使用 Node 22；最终用户无需安装）
python -m pip install -r requirements.txt pytest
python -m pytest -q -rs
python scripts/check_ui_js.py
python scripts/package_desktop.py --arch x64
# 已安装 Inno Setup 6 时生成安装程序
python scripts/package_desktop.py --arch x64 --installer
```

macOS 在对应架构机器上执行 `python3 scripts/package_desktop.py --arch arm64` 或 `--arch x64`。脚本使用 onedir/app bundle，核对 Python 实际架构，并从临时工作目录启动 `--self-check` 验证资源和写入目录；不支持跨 OS 编译。Linux 继续保留 `plcn.spec` 的 CLI 打包。

构建后可验证实际分发包（CI 对 Windows、macOS 两种架构均执行）：

```bash
python scripts/smoke_desktop_package.py --installer dist/PLCN-Windows-x64-Setup.exe
python scripts/smoke_desktop_package.py --dmg dist/PLCN-macOS-arm64.dmg
```

Windows 验收会静默安装到临时中文路径，运行程序后卸载，检查注册项清理和用户数据保留；若系统已有 PLCN 安装器注册项则拒绝运行，请使用干净测试机。macOS 会只读挂载 DMG，复制应用后卸载镜像，再启动复制出的程序。两者都验证资源、同配置重复启动、不同配置端口隔离和正常退出。所有用户数据使用临时 `PLCN_HOME`，不会修改日常配置。失败时日志目录保留并打印到终端。

便携版本可以使用 `--binary <可执行文件路径>` 做同样的程序验收。`PLCN --no-browser` 可启动服务而不打开浏览器，供自动验收使用。这些检查不覆盖系统文件选择器、Gatekeeper、SmartScreen 或签名验收。

## 签名与正式发布

桌面 CI 在 Windows x64、macOS Intel、Apple Silicon 上构建，产物明确命名为 `unsigned`。Tag 工作流只创建草稿预发布，保留 Linux CLI；不会直接发布未经人工验收的稳定版本。

macOS：将自己的 Developer ID Application 证书导入构建机器钥匙串，通过环境变量 `PLCN_CODESIGN_IDENTITY` 指定身份后重新构建。PyInstaller 会签署内部二进制，应用使用 `packaging/macos-entitlements.plist`；仍需检查 hardened runtime 和最终嵌套签名。构建后提交 DMG：

```bash
codesign --verify --deep --strict --verbose=2 dist/PLCN.app
codesign -d --verbose=4 dist/PLCN.app
xcrun notarytool submit dist/PLCN-macOS-arm64.dmg --keychain-profile PLCN-notary --wait
xcrun stapler staple dist/PLCN-macOS-arm64.dmg
xcrun stapler validate dist/PLCN-macOS-arm64.dmg
spctl --assess --type execute --verbose=4 dist/PLCN.app
```

`PLCN-notary` 是发布者自己事先配置的钥匙串 profile，占位名称不代表已存在凭据；Intel 产物同样处理。公证后从下载的 DMG 安装并检查 Gatekeeper、启动、文件选择和写回。不要仅因 CI 上自检成功就认为下载隔离环境也通过。

Windows：使用自己的代码签名证书和 Windows SDK `signtool` 签署 `dist/PLCN/PLCN.exe`，再生成安装程序和便携 ZIP，随后签署 Setup.exe，并用 `signtool verify /pa` 验证。证书密码只经发布环境/密钥库注入，不提交仓库。当前没有导入或申请任何签名证书。

正式发布前还需人工验收：安装/卸载与升级后配置保留、非 ASCII 路径、只读程序目录、双击重复启动、系统文件选择器、关闭/取消、恢复、真实 ADB 与外接卷断开。桌面 UI 的完整键盘/多语言检查继续保留为发布检查项。

首页会自动检测 USB 设备及默认 RetroArch 目录，展示可用、未授权和离线状态；检测不会自动打开游戏库。点击设备旁的“打开游戏库”后进入列表。“最近使用”保留最近 5 个成功打开的游戏库，显示具体路径与可用状态；历史保存在 PLCN 用户数据目录。也可使用“打开本地目录”或“手动输入路径”。检测或打开失败的原因会持续显示，可点击“重新检测”重试。在游戏库的“管理”菜单中选择“打开其他游戏库”可返回首页。

当多个 ROM 的列表名称映射到同一图片文件时，单项补图窗口会列出共用条目，并要求核对当前 ROM 的独立名称。确认后仅更新当前条目的名称、创建独立图片，并备份游戏列表；原共用图片和其他条目保持不变，其他类型图片复制到独立名称下。共用标签不再直接作为当前游戏英文名的识别依据。预览不写入设备，写入结果不确定时可使用原预览重试。

SNES 的“火焰之纹章3、4、5”等编号 ROM 名称分别识别为 Monshou no Nazo、Seisen no Keifu、Thracia 776，再自动搜索官方图库。此匹配来自名称别名，仍需核对候选图片与版本。空搜索词会提示输入名称，不发送无效图库请求。

批量图片下载遇到 404 时会查询官方图库目录，处理空格、语言标记和已知 PCE 标题别名的差异；地区、修订版和续作仍必须一致，多个候选无法唯一确定时保留失败结果。任务结束时分别显示列表写回和图片下载结果；图片失败会标记“部分完成”。

修复预览不再要求逐项人工确认。已识别名称和图片源的待处理条目默认勾选，可直接批量应用；无需修改的条目显示“无需修复”，缺少必要名称或图片源的条目显示“待补充”。匹配分数继续作为参考信息，编辑名称或图片源后可以直接应用。游戏列表的变更校验、备份和图片文件名冲突检查继续生效。

### RetroArch 与 PLCN 的图片一致性

RetroArch 1.20 读取本地缩略图时依次尝试 ROM 文件名、完整列表名称、去掉括号后缀的列表名称。PLCN 的游戏列表和图片预览使用同样的 ROM 文件名优先规则。单游戏更换图片时，如已有 ROM 文件名图片，会与列表名称图片一起更新并备份；如果该文件也被其他条目引用，会说明冲突并停止写入。写入中断可以重试，成功后重新读取设备列表，不再只替换页面中的临时图片。

更换图片窗口也可以修改未共用图片的游戏名称，避免拆分到最后一个条目后无法修正残留旧名。封面、游戏截图、标题图是三个独立类型，更换一个类型不会自动修复其他类型的内容。外部修改设备列表前先退出 RetroArch，完成后重新打开，让它重新加载列表和图片。

### 光盘游戏显示

PS、Saturn、Dreamcast 等光盘游戏常同时包含 `.cue` 描述文件和一个或多个 `.bin/.img` 数据文件。PLCN 在当前游戏列表和批量预览中只显示同目录同名的一组光盘文件中的一条，优先选择 `.m3u`、`.cue`、`.chd`、`.iso` 或 `.gdi`；附属数据文件仍保留在设备上，不会被删除。单独的 `.bin/.img` 没有被同组描述文件引用时会继续显示。
