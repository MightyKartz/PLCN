# PLCN 桌面预览版使用与发布

本轮是 v3.3 桌面体验版；当前发行版为 v3.3.1，历史发行版从 v3.2.5 起提供内置 ADB 的 Windows / macOS 安装包。桌面基础 PR：[MightyKartz/PLCN#5](https://github.com/MightyKartz/PLCN/pull/5)，UI 精简 PR：[MightyKartz/PLCN#6](https://github.com/MightyKartz/PLCN/pull/6)。

## 普通用户

Windows：安装 `PLCN-Windows-x64-Setup.exe` 后，从开始菜单启动；也可以解压便携 ZIP 后双击 `PLCN/PLCN.exe`。便携包默认仍使用用户数据目录，程序升级不会覆盖配置。

macOS：选择对应架构的 `PLCN-macOS-arm64.dmg`（Apple Silicon）或 `PLCN-macOS-x64.dmg`（Intel），将 PLCN.app 拖到 Applications。当前 CI 产物为未签名/未公证预览，不能作为正式分发就绪的声明；发布者应完成下方签名验收。

打开后出现浏览器工作台，关闭标签不停止服务。再次启动会打开已有服务，不创建第二个实例。需要停止时用“设置 → 退出 PLCN”，有运行任务时会提示先等待或取消。

1. 在首页选择已连接的游戏库，或打开电脑、SD 卡上的 RetroArch / playlists 目录；也可“手动输入路径”后扫描。“设置 → 游戏库”只保留“游戏库目录”和“图片目录（可选覆盖）”，列表和系统名称由左侧选择决定。图片目录留空时自动检测；手动覆盖适用于当前库的所有主机，切换主机、刷新并重开当前库后保留，打开其他库时清除。扫描完成后，在左侧选择主机或具体列表，右侧立即显示当前名称、ROM 文件名和已有图片；浏览不执行名称匹配或写回。
2. 点击标题栏“整理本主机”直接预览名称与图片。预览顶部的“修改名称”“补全图片”默认都勾选；取消其一即仅改名或仅补图，至少保留一项。选项变化会重新分析，旧的行内编辑和勾选清除。仅补图按原 label 保存图片，本地与 ADB 都不改写 `.lpl`。
3. 预览默认显示带数量的“全部 / 待补充 / 可应用”，其他条件在“筛选”中展开。表格从左到右是勾选、游戏名称、修复状态、封面源英文名、封面状态：名称和图片源点击后编辑，Enter 或失焦提交、Esc 取消；ROM 副标题悬停可查看完整路径，修复理由也保留悬停说明。行点击不再打开右侧面板，顶部不再显示流程条。编辑过的行可点“记住修正”，保存本地规则后重新预览；核对后点击“应用 N 项变更”，查看摘要并确认。点击筛选“全部”不会改变勾选。官方图库缺图时，行内“更换图片”仍可打开补图窗口，搜索官方或备用图库、导入本地图片；备用图必须手动选中后才写入。

    处理整个库时，点击左侧主机列表上方“整理全部主机”。程序只读分析并列出各主机的改名游戏数、补图游戏数、待补充数及读取错误；在汇总窗口中选择名称／图片选项会重新生成汇总。确认前不写入，关闭窗口即放弃本次汇总。点击“确认应用全部变更”只应用汇总时保存的提案和选项，写回名称前自动备份；列表在汇总后发生变化则拒绝处理该列表，需重新生成汇总。默认遇到错误继续其他主机，也可以取消此选项。

4. “设置 → 任务与恢复”集中显示本次运行的进度、错误和任务明细，替代旧底部任务栏及详情抽屉。展开明细可查看最近 200 条处理记录、三类图片汇总、未完成图片与列表错误；无失败时展示最近 200 条图片结果，轮询时保留展开状态。运行中的进度提示提供“查看任务”入口，设置窗口的关闭按钮在滚动时保持可见。可以取消、重试未完成的本地图片；设备 URI 不传入本地下载器，设备补图请使用游戏行的补图窗口。取消在安全边界生效，已写回的名称、已下载的图片会保留。当前网络请求/数据包构建结束前可能仍显示运行中。
5. “设置 → 任务与恢复”中的恢复记录列出最近 100 条本地列表写回记录。恢复前检查列表与备份的摘要，列表被其它程序修改则拒绝覆盖；同时保留恢复前备份。图片不会随列表恢复删除。ADB 备份仍在设备上，当前需手动恢复。

更换目录或手动修改路径后，旧预览会清除；在预览中切换操作选项会清除旧编辑并重新分析。运行期间输入和应用操作锁定；进度连接断开时保留锁定并自动重连，避免重复提交。再次启动可从“最近使用”重开游戏库，不会自动扫描未连接的设备。首页无可用设备时可展开“Android 掌机连接帮助”，按开发者选项、USB 调试和电脑授权步骤操作，再重新检测。

左侧主机导航显示每个主机的游戏数量，支持搜索；同一主机有多个列表时展开具体列表，单列表不重复显示卡片。目录设置在“设置 → 游戏库”中。游戏区顶部提供搜索及“全部 / 缺图 / 需检查”筛选：图片目录已配置且三类图片全缺时，图片列只显示“缺图”；仅部分缺失或有损坏时展开“封面 / 游戏截图 / 标题图”三枚状态标签（✓ 已有、○ 缺少、! 损坏）。“缺图”列出任意一类缺失的游戏，未设置图片目录时在列表顶部集中提示并提供“指定图片目录”，不计入单游戏的“需检查”；损坏图片或设备读取失败仍归入“需检查”，整份列表的修复入口为标题栏的“整理本主机”。压缩包路径如 `中文名.zip#Bikkuriman World (Japan).pce` 在 ROM 列只显示内部文件名，悬停可查看完整路径；英文名识别也使用同一内部文件名，实际 ROM 路径保持原样。

### 只更新一个游戏的图片

窗口标题会区分三种情况：还没有图片时“为这个游戏补图”、只缺部分类型时“补齐缺少的图片”、三类齐全时“更换游戏图片”。三种图片类型可分别勾选，未勾选的不受影响。

在当前游戏列表中，点击该行的“补图”或“更换图片”，程序先识别英文名并自动搜索 RetroArch / Libretro 官方图库。搜索框同时接受中文名和英文名：中文名先由本地名称库转换成候选英文名，列出中文名与匹配度供核对，点选后才去搜索图库——程序不会自动采用模糊结果。优先复用上次确认的图片源，再查询当前主机的名称库和 ROM 文件名；名称存在歧义时先选择游戏名称。候选按匹配强度分级（完整名称匹配、包含全部关键词、名称相近），只有更严格的级别没有结果时才降级，并保留地区版本供核对。自动搜索限定同一游戏，并将完整名称匹配放在前面。找不到名称、图库没有图片和网络失败会分别提示。

窗口自动搜索并列出官方候选，名称有歧义时先选择名称。候选以图片卡片展示，点击卡片即预览，自动滚动到当前图片与候选图片的对比；不再需要单独点击“预览图片”。确认后才写入。官方没有结果时显示“搜索备用来源”，点击才查询备用图库；备用候选同样需要手动选择、预览和确认，永不批量自动采用。可以修改英文名后重新搜索，或导入 PNG、JPEG、WebP 本地图片（最多 12 MiB，格式说明在导入控件提示中）；搜索期间本地导入始终可用。成功确认的在线图片源保存在用户数据目录的 `artwork-sources.json`，按游戏和图片类型复用，不改变名称数据库或游戏名称。

核对候选图片和保存位置后，点击“确认”。此操作只更新当前游戏所选类型的一张图片，不改名称或 `.lpl`，支持本地目录和 ADB 设备。替换时在原图旁保留 `.bak-…` 备份，校验成功后自动关闭弹窗、回到该游戏行并显示新图和结果；将指针停留在备份提示上可查看备份路径。缺失、损坏和读取失败分别提示。传输失败时保留弹窗供重试，任务状态暂时失联时“查询更新结果”会继续查询原任务。

图片按当前列表名称保存，预览后列表或目标图片发生变化会拒绝写入，需要重新预览。两个条目共用同一图片文件名时，不允许通过单游戏操作覆盖共享图片。图片备份暂需手动恢复。

系统文件选择器运行于独立 helper 的主线程；不可用时自动回退内置文件浏览。原生选择器的真实桌面交互仍在人工验收清单中。

## 数据库更新

“设置 → 名称数据库”提供检查上游版本、下载并比较、比较已安装包、启用和回滚。在同一面板查看新增、移除、译名变化和未翻译数量后再启用；这些数量不是准确率评估。切换会清除旧预览，人工规则保留。首次数据导入可能需要等待几秒，之后使用缓存。

数据包在应用数据目录的 `packs/`；比较普通 CSV 时创建可复用的 baseline 快照。更新包不自动启用。启动时不会自动联网更新名称数据；DAT 未缓存时仍沿用现有按需下载行为。失败图片重试不会再次改名；命名冲突和 ADB 推送不在此重试入口中，需修正后重新预览。

## 数据存储与迁移

| 内容 | Windows | macOS |
| --- | --- | --- |
| 配置、规则、数据包、历史、日志 | `%LOCALAPPDATA%\PLCN` | `~/Library/Application Support/PLCN` |
| 可重建缓存、DAT | `%LOCALAPPDATA%\PLCN\cache` | `~/Library/Caches/PLCN` |

Linux 使用 XDG 用户数据/缓存目录。`PLCN_HOME` 可显式指定独立数据目录，用于便携场景和测试；设置后缓存也放在该目录下。它应为可写、仅当前用户使用的目录。

首次启动复制已知旧程序目录中的 `config.json` 与人工规则，不删除原件；将旧相对路径转换为绝对路径，失效的内置数据路径改回资源默认值。已有新配置不覆盖。迁移记录为 `migration.json`，桌面日志为 `logs/desktop.log`，超过 5 MiB 时在下次启动轮换。之前自行移动程序、把配置放在其它目录的情况，需从高级设置重新选择路径或手动迁移。

源文件与内置名称数据只读使用；运行时不再依赖安装目录可写。根目录旧版 `plcn.db` 不再使用，可以删除；当前缓存可从 CSV 重建。原始列表和相邻备份仍留在用户游戏库。

## 从源码与本地打包

正式用户直接使用 GitHub Release 中的安装包，不需要安装 Xcode、Node.js 或接受任何 SDK 许可。下面的打包命令只面向维护者；CI 已包含许可和依赖环境。若本机 macOS 手动构建，`lipo`/PyInstaller 可能要求先在本机同意 Xcode license，这是开发打包步骤，不是用户安装步骤。

```powershell
# Windows，项目根目录
.\venv\Scripts\python.exe src\plcn.py ui
# 无控制台入口（系统的 pythonw 或虚拟环境 pythonw）
.\venv\Scripts\pythonw.exe src\desktop.py

# 测试与 JS 检查需要 Node.js（CI 使用 Node 22；最终用户无需安装）
python -m pip install -r requirements.txt pytest
python -m pytest -q -rs
python scripts/check_ui_js.py
python scripts/package_desktop.py --arch x64
# 已安装 Inno Setup 6 时生成安装程序
python scripts/package_desktop.py --arch x64 --installer
```

浏览器冒烟测试随 `pytest` 运行，也可以单独执行 `python -m pytest -q tests/python/test_browser_smoke.py`。需要 Node.js 22 或更新版本，以及 Chrome / Chromium；不需要 ChromeDriver 或额外 npm 依赖。测试在独立用户数据和浏览器配置目录内，使用离线名称样本及复制的列表，在 1440×900 和 1100×700 下完成“首页 → 打开本地库 → 切换主机 → 生成预览”，验证中文名称、关键控件可见性和无页面 JavaScript 异常，并检查列表文件未被改写。

默认自动查找浏览器，可用环境变量 `CHROME_BIN` 指定可执行文件的完整路径。未找到浏览器时会明确跳过；设置 `PLCN_REQUIRE_BROWSER=1` 则会失败，回归 CI 的 Ubuntu / Python 3.13 任务强制启用此检查。截图和日志保存在 `output/playwright/browser-smoke/`，失败时额外保存页面 HTML、截图及错误信息，CI 会上传该目录。

后端按领域拆分：`api_routes.py` 注册 GET / POST 路径，`api_library.py`、`api_playlists.py`、`api_artwork.py`、`api_tasks.py`、`api_data.py`、`api_desktop.py`、`api_config.py` 实现接口；`server.py` 负责同源会话、请求解析、静态资源及服务启动。处理函数接收请求、运行上下文和已解析的参数，配置路径与任务管理器始终由当前服务提供；新增接口应在路由表中显式注册。

`plcn.py` 只处理 CLI 参数与分发，`playlist_service.py` 是统一公开入口，通过显式导出保留原有函数和提案类型；HTTP 与 CLI 使用同一核心，核心不依赖服务启动。内部职责如下：

- `playlist_analysis.py`：名称、ROM、DAT 证据分析与提案生成。
- `playlist_proposals.py`：提案数据结构、匹配元数据、标识及原始条目快照校验。
- `playlist_artwork.py`：只读查找本地／ADB 图片，供分析与游戏列表浏览复用。
- `playlist_writeback.py`：文件锁、汇总摘要校验、备份、写回、回读验证及图片任务。
- `playlist_batch.py`：原有 CLI 单列表和目录处理流程；HTTP 的“先汇总再确认”仍由 `batch_review.py` 管理。

只读图片查找和写回模块可以独立导入，不加载分析器或名称翻译器。修改依赖或测试替换点时，在实际拥有该依赖的模块操作，统一入口不再复制这些内部依赖。

`batch_review.py` 保存只读汇总所需的提案与文件摘要，`playlist_transport.py` 复用本地／ADB 写回协议；`job_manager.py` 管理任务状态，`job_results.py` 转换任务结果；原 `desktop_api.py` 已由上述领域模块替代。

macOS 在对应架构机器上执行 `python3 scripts/package_desktop.py --arch arm64` 或 `--arch x64`。脚本使用 onedir/app bundle，核对 Python 实际架构，并从临时工作目录启动 `--self-check` 验证资源和写入目录；不支持跨 OS 编译。Linux 继续保留 `plcn.spec` 的 CLI 打包。

构建后可验证实际分发包（CI 对 Windows、macOS 两种架构均执行）：

```bash
python scripts/smoke_desktop_package.py --installer dist/PLCN-Windows-x64-Setup.exe
python scripts/smoke_desktop_package.py --dmg dist/PLCN-macOS-arm64.dmg
```

Windows 验收会静默安装到临时中文路径，运行程序后卸载，检查注册项清理和用户数据保留；若系统已有 PLCN 安装器注册项则拒绝运行，请使用干净测试机。macOS 会只读挂载 DMG，复制应用后卸载镜像，再启动复制出的程序。两者都验证资源、同配置重复启动、不同配置端口隔离和正常退出。所有用户数据使用临时 `PLCN_HOME`，不会修改日常配置。失败时日志目录保留并打印到终端。

便携版本可以使用 `--binary <可执行文件路径>` 做同样的程序验收。`PLCN --no-browser` 可启动服务而不打开浏览器，供自动验收使用。这些检查不覆盖系统文件选择器、Gatekeeper、SmartScreen 或签名验收。

## 签名与正式发布

当前发布策略不购买签名证书，继续提供未签名、未公证产物。以下签名流程保留作未来参考，不属于当前实施范围。

桌面 CI 在 Windows x64、macOS Intel、Apple Silicon 上构建，产物明确命名为 `unsigned`。Tag 工作流只创建草稿预发布，保留 Linux CLI；不会直接发布未经人工验收的稳定版本。

macOS：将自己的 Developer ID Application 证书导入构建机器钥匙串，通过环境变量 `PLCN_CODESIGN_IDENTITY` 指定身份后重新构建。PyInstaller 会签署内部二进制，应用使用 `packaging/macos-entitlements.plist`；仍需检查 hardened runtime 和最终嵌套签名。构建后提交 DMG：

```bash
codesign --verify --deep --strict --verbose=2 dist/PLCN.app
codesign -d --verbose=4 dist/PLCN.app
xcrun notarytool submit dist/PLCN-macOS-arm64.dmg --keychain-profile PLCN-notary --wait
xcrun stapler staple dist/PLCN-macOS-arm64.dmg
xcrun stapler validate dist/PLCN-macOS-arm64.dmg
spctl --assess --type execute --verbose=4 dist/PLCN.app
```

`PLCN-notary` 是发布者自己事先配置的钥匙串 profile，占位名称不代表已存在凭据；Intel 产物同样处理。公证后从下载的 DMG 安装并检查 Gatekeeper、启动、文件选择和写回。不要仅因 CI 上自检成功就认为下载隔离环境也通过。

Windows：使用自己的代码签名证书和 Windows SDK `signtool` 签署 `dist/PLCN/PLCN.exe`，再生成安装程序和便携 ZIP，随后签署 Setup.exe，并用 `signtool verify /pa` 验证。证书密码只经发布环境/密钥库注入，不提交仓库。当前没有导入或申请任何签名证书。

正式发布前还需人工验收：安装/卸载与升级后配置保留、非 ASCII 路径、只读程序目录、双击重复启动、系统文件选择器、关闭/取消、恢复、真实 ADB 与外接卷断开。桌面 UI 的完整键盘/多语言检查继续保留为发布检查项。

首页会自动检测 USB 设备及默认 RetroArch 目录，展示可用、未授权和离线状态；检测不会自动打开游戏库。点击设备旁的“打开游戏库”后进入列表。“最近使用”保留最近 5 个成功打开的游戏库，显示具体路径与可用状态；历史保存在 PLCN 用户数据目录。也可使用“打开本地目录”或“手动输入路径”。检测或打开失败的原因会持续显示，可点击“重新检测”重试。在游戏库的“管理”菜单中选择“打开其他游戏库”可返回首页。

当多个 ROM 的列表名称映射到同一图片文件时，单项补图窗口会列出共用条目，并要求核对当前 ROM 的独立名称。确认后仅更新当前条目的名称、创建独立图片，并备份游戏列表；原共用图片和其他条目保持不变，其他类型图片复制到独立名称下。共用标签不再直接作为当前游戏英文名的识别依据。预览不写入设备，写入结果不确定时可使用原预览重试。

SNES 的“火焰之纹章3、4、5”等编号 ROM 名称分别识别为 Monshou no Nazo、Seisen no Keifu、Thracia 776，再自动搜索官方图库。此匹配来自名称别名，仍需核对候选图片与版本。空搜索词会提示输入名称，不发送无效图库请求。

批量图片下载遇到 404 时会查询官方图库目录，处理空格、语言标记和已知 PCE 标题别名的差异；地区、修订版和续作仍必须一致，多个候选无法唯一确定时保留失败结果。任务结束时分别显示列表写回和图片下载结果；图片失败会标记“部分完成”。

修复预览不再要求逐项人工确认。已识别名称和图片源的待处理条目默认勾选，可直接批量应用；无需修改的条目显示“无需修复”，缺少必要名称或图片源的条目显示“待补充”。匹配分数继续作为参考信息，编辑名称或图片源后可以直接应用。游戏列表的变更校验、备份和图片文件名冲突检查继续生效。

### RetroArch 与 PLCN 的图片一致性

RetroArch 1.20 读取本地缩略图时依次尝试 ROM 文件名、完整列表名称、去掉括号后缀的列表名称。PLCN 的游戏列表和图片预览使用同样的 ROM 文件名优先规则。单游戏更换图片时，如已有 ROM 文件名图片，会与列表名称图片一起更新并备份；如果该文件也被其他条目引用，会说明冲突并停止写入。写入中断可以重试，成功后重新读取设备列表，不再只替换页面中的临时图片。

更换图片窗口也可以修改未共用图片的游戏名称，避免拆分到最后一个条目后无法修正残留旧名。封面、游戏截图、标题图是三个独立类型，更换一个类型不会自动修复其他类型的内容；游戏列表的图片列用同样的三类名称与状态标签展示，三类标签保持一行，缩小缩略图后一屏可以多显示约三成游戏。每行的“补图 / 更换图片”在鼠标悬停或键盘聚焦时出现，减少整列重复按钮；需要时把指针移到该行即可。补图完成后结果以底部提示显示，不再占用顶部筛选栏。外部修改设备列表前先退出 RetroArch，完成后重新打开，让它重新加载列表和图片。

### 光盘游戏显示

PS、Saturn、Dreamcast 等光盘游戏常同时包含 `.cue` 描述文件和一个或多个 `.bin/.img` 数据文件。PLCN 在当前游戏列表和批量预览中把同一个碟的描述文件与附属数据合并成一条，优先选择 `.cue`、`.chd`、`.iso` 或 `.gdi`；附属数据文件仍保留在设备上，不会被删除。多碟游戏（`(Disc 1)`、`(Disc 2)`）在没有 `.m3u` 时每碟各显示一条，与 RetroArch 自身一致，切碟和每碟单独补图都保留；如果列表里有对应的 `.m3u`，则只显示 `.m3u` 这一条，它列出的碟文件不再重复出现。单独的 `.bin/.img` 没有被同组描述文件引用时会继续显示。

## 分发说明（v3.2.5 起）

Windows / macOS 包内置 Google Platform Tools 37.0.1 的 ADB 及必要依赖、NOTICE；不包含完整 Android SDK。构建时运行 `scripts/prepare_adb.py`，核验固定 SHA256，归档变化时构建失败，需维护者审核后更新校验值。

安装包自检直接调用内置 ADB 的 `version`，不依赖开发机 PATH。Windows 仍可能需要设备厂商 USB 驱动，Android 端必须授权 USB 调试。下载正确架构的 Release 附件即可双击启动；Source code 不属于安装包。

GitHub 自动构建目前没有配置发行签名凭据，Windows 包未签名，Mac 包只有构建所需的临时签名、未公证。本机存在 Developer ID 不代表 CI 已使用它。配置证书和公证凭据后，才能单独验证 Gatekeeper 的首次下载体验；不要把 CI 启动测试当作公证成功。
