# RetroArch 助手：使用与发布

本次开发分支已更名为 RetroArch 助手，以下安装包名称对应更名后的构建；历史 Release 仍使用 PLCN 前缀，尚未发布新的更名安装包。

本轮是 v3.3 桌面体验版；当前发行版为 v3.3.1，历史发行版从 v3.2.5 起提供内置 ADB 的 Windows / macOS 安装包。桌面基础 PR：[MightyKartz/retroarch-assistant#5](https://github.com/MightyKartz/retroarch-assistant/pull/5)，UI 精简 PR：[MightyKartz/retroarch-assistant#6](https://github.com/MightyKartz/retroarch-assistant/pull/6)。

## 普通用户

Windows：安装 `RetroArchAssistant-Windows-x64-Setup.exe` 后，从开始菜单启动；也可以解压便携 ZIP 后双击 `RetroArchAssistant/RetroArchAssistant.exe`。便携包默认仍使用用户数据目录，程序升级不会覆盖配置。

macOS：选择对应架构的 `RetroArchAssistant-macOS-arm64.dmg`（Apple Silicon）或 `RetroArchAssistant-macOS-x64.dmg`（Intel），将 `RetroArch Assistant.app` 拖到 Applications。当前 CI 产物为未签名/未公证预览，不能作为正式分发就绪的声明；发布者应完成下方签名验收。

双击启动后打开独立窗口。再次启动会唤回已有窗口。关闭窗口或选择“设置 → 退出 RetroArch 助手”会停止本地服务，活动任务会阻止退出。

1. 在首页选择已连接掌机的游戏库，或“手动指定设备目录”后扫描。首页不探测电脑本地目录或本地最近记录。macOS 连接 Android 掌机时选择 USB“文件传输”并保持解锁即可，无须 USB 调试；请关闭其它正在占用设备的文件传输程序。“设置 → 常规”可直接切换语言和外观，并显示游戏库目录。掌机目录默认显示文件夹名称，可通过“编辑路径”查看完整地址。外观默认跟随系统，也可固定为浅色或深色。图片目录自动跟随游戏库，只有需要指定目录或已设置覆盖值时才显示该选项。库中没有图片目录时，首次补图会自动创建 `<游戏库>/thumbnails`。手动指定的目录适用于当前库的所有主机，切换主机或重新打开当前库时保留，切换游戏库时清除。扫描完成后默认选中左侧列表顶部的“全部主机”；在左侧选择主机或具体列表，右侧立即显示当前名称、ROM 文件名和已有图片；浏览不执行名称匹配或写回。
2. 选中主机后点击标题栏“一键补全”直接预览名称与图片，入口旁提示：“自动匹配中文名与图片，预览后确认应用。”预览顶部的“修改名称”“补全图片”默认都勾选；取消其一即仅改名或仅补图，至少保留一项。选项变化会重新分析，旧的行内编辑和勾选清除。仅补图按原 label 保存图片，本地、ADB 与 macOS MTP 都不改写 `.lpl`。
3. 预览默认显示带数量的“全部 / 待补充 / 可应用”，其他条件在“筛选”中展开。表格从左到右是勾选、游戏名称、修复状态、封面源英文名、封面状态：名称和图片源点击后编辑，Enter 或失焦提交、Esc 取消；ROM 副标题悬停可查看完整路径，修复理由也保留悬停说明。行点击不再打开右侧面板，顶部不再显示流程条。编辑过的行可点“记住修正”，保存本地规则后重新预览；预览页自动显示已选、改名和补图数量；核对后点击“确认应用 N 项”直接执行，不再出现第二次确认。点击筛选“全部”不会改变勾选。官方图库缺图时，行内“更换图片”仍可打开补图窗口，搜索官方或备用图库、导入本地图片；备用图必须手动选中后才写入。

    处理整个库时，保持左侧主机列表顶部默认选中的“全部主机”，点击右上角“一键补全”。程序先分析全部主机（此步不写入），随后直接应用：写回名称前自动备份，列表在分析后发生变化则拒绝处理该列表，遇到错误继续其他主机。完成后窗口按主机列出改名、补图、需手动处理与结果，运行中可随时取消，已完成的部分保留。没有选项或确认步骤；应用的是分析时保存的提案。库中没有图片目录时使用 `<游戏库>/thumbnails`，首次补图时自动创建；可在图片目录无法自动确定时手动指定。选中单个主机时，“一键补全”仍是先预览后确认。

4. 补全运行时可在进度提示中取消，完成后可从结果提示直接撤销。取消在安全边界生效，已完成的部分会保留。

更换目录或手动修改路径后，旧预览会清除；在预览中切换操作选项会清除旧编辑并重新分析。运行期间输入和应用操作锁定；进度连接断开时保留锁定并自动重连，避免重复提交。再次启动可从“最近使用”重开游戏库，不会自动扫描未连接的设备。首页无可用设备时可展开“Android 掌机连接帮助”，按开发者选项、USB 调试和电脑授权步骤操作，再重新检测。

左侧主机导航显示每个主机的游戏数量，支持搜索；同一主机有多个列表时展开具体列表，单列表不重复显示卡片。目录设置在“设置 → 常规”中。游戏区顶部提供搜索及“全部 / 缺图 / 需检查”筛选：图片目录已配置且三类图片全缺时，图片列只显示“缺图”；仅部分缺失或有损坏时展开“封面 / 游戏截图 / 标题图”三枚状态标签（✓ 已有、○ 缺少、! 损坏）。“缺图”列出任意一类缺失的游戏，未设置图片目录时在列表顶部集中提示并提供“指定图片目录”，不计入单游戏的“需检查”；损坏图片或设备读取失败仍归入“需检查”，整份列表的修复入口为标题栏的“一键补全”。压缩包路径如 `中文名.zip#Bikkuriman World (Japan).pce` 在 ROM 列只显示内部文件名，悬停可查看完整路径；英文名识别也使用同一内部文件名，实际 ROM 路径保持原样。

### 只更新一个游戏的图片

窗口标题会区分三种情况：还没有图片时“为这个游戏补图”、只缺部分类型时“补齐缺少的图片”、三类齐全时“更换游戏图片”。三种图片类型可分别勾选，未勾选的不受影响。

在当前游戏列表中，点击该行的“补图”或“更换图片”，程序先识别英文名并自动搜索 RetroArch / Libretro 官方图库。搜索框同时接受中文名和英文名：中文名先由本地名称库转换成候选英文名，列出中文名与匹配度供核对，点选后才去搜索图库——程序不会自动采用模糊结果。优先复用上次确认的图片源，再查询当前主机的名称库和 ROM 文件名；名称存在歧义时先选择游戏名称。候选按匹配强度分级（完整名称匹配、包含全部关键词、名称相近），只有更严格的级别没有结果时才降级，并保留地区版本供核对。自动搜索限定同一游戏，并将完整名称匹配放在前面。找不到名称、图库没有图片和网络失败会分别提示。

窗口自动搜索并列出官方候选，名称有歧义时先选择名称。候选以图片卡片展示，点击卡片即预览，自动滚动到当前图片与候选图片的对比；不再需要单独点击“预览图片”。确认后才写入。官方没有结果时显示“搜索备用来源”，点击才查询备用图库；备用候选同样需要手动选择、预览和确认，永不批量自动采用。可以修改英文名后重新搜索，或导入 PNG、JPEG、WebP 本地图片（最多 12 MiB，格式说明在导入控件提示中）；搜索期间本地导入始终可用。成功确认的在线图片源保存在用户数据目录的 `artwork-sources.json`，按游戏和图片类型复用，不改变名称数据库或游戏名称。

核对候选图片和保存位置后，点击“确认”。此操作只更新当前游戏所选类型的一张图片，不改名称或 `.lpl`，支持本地目录、ADB 设备和 macOS MTP 文件传输。替换时在原图旁保留 `.bak-…` 备份，校验成功后自动关闭弹窗、回到该游戏行并显示新图和结果；将指针停留在备份提示上可查看备份路径。缺失、损坏和读取失败分别提示。传输失败时保留弹窗供重试，任务状态暂时失联时“查询更新结果”会继续查询原任务。

图片按当前列表名称保存，预览后列表或目标图片发生变化会拒绝写入，需要重新预览。两个条目共用同一图片文件名时，不允许通过单游戏操作覆盖共享图片。图片备份暂需手动恢复。

独立窗口直接打开系统文件选择器，浏览器模式通过独立进程打开。系统选择器不可用时回退到工作台内置浏览。

## 浏览器模式与开发入口

macOS 使用系统 WKWebView，Windows 使用 WebView2 Runtime。Windows 缺少运行时会使用默认浏览器。浏览器模式下，关闭标签后本地服务继续运行，可从应用设置退出。切换模式前先退出原有实例。两种模式沿用同一用户数据目录，语言和外观由各自的浏览器或 WebView 保存。

```sh
# macOS 浏览器模式
open -a "RetroArch Assistant" --args --browser
# Windows 便携版浏览器模式
.\RetroArchAssistant.exe --browser
# 从源码打开独立窗口
python -m pip install -r requirements-desktop.txt
python src/desktop.py
```

`--window` 可显式要求独立窗口，`--no-browser` 可只启动服务。现有 CLI 的 `ui` 命令仍打开浏览器。

## 数据库更新

“设置 → 名称数据库”提供检查上游版本、下载并比较、比较已安装包、启用和回滚。在同一面板查看新增、移除、译名变化和未翻译数量后再启用；这些数量不是准确率评估。切换会清除旧预览，人工规则保留。首次数据导入可能需要等待几秒，之后使用缓存。

数据包在应用数据目录的 `packs/`；比较普通 CSV 时创建可复用的 baseline 快照。更新包不自动启用。启动时不会自动联网更新名称数据；DAT 未缓存时仍沿用现有按需下载行为。失败图片重试不会再次改名；命名冲突和 ADB 推送不在此重试入口中，需修正后重新预览。

## 数据存储与迁移

| 内容 | Windows | macOS |
| --- | --- | --- |
| 配置、规则、数据包、历史、日志 | `%LOCALAPPDATA%\RetroArchAssistant` | `~/Library/Application Support/RetroArchAssistant` |
| 可重建缓存、DAT | `%LOCALAPPDATA%\RetroArchAssistant\cache` | `~/Library/Caches/RetroArchAssistant` |

Linux 使用 XDG 用户数据/缓存目录。`RETROARCH_ASSISTANT_HOME` 可显式指定独立数据目录，用于便携场景和测试；设置后缓存也放在该目录下。它应为可写、仅当前用户使用的目录。

首次启动只创建新数据目录，不会自动读取旧位置。升级用户应先执行[一次性迁移](MIGRATION.md)。桌面日志为 `logs/desktop.log`，超过 5 MiB 时在下次启动轮换。

源文件与内置名称数据只读使用；运行时不依赖安装目录可写。名称缓存数据库为 `library.db`，可从 CSV 重建。原始列表和相邻备份仍留在用户游戏库。

## 从源码与本地打包

正式用户直接使用 GitHub Release 中的安装包，不需要安装 Xcode、Node.js 或接受任何 SDK 许可。下面的打包命令只面向维护者；CI 已包含许可和依赖环境。若本机 macOS 手动构建，`lipo`/PyInstaller 可能要求先在本机同意 Xcode license，这是开发打包步骤，不是用户安装步骤。

```powershell
# Windows，项目根目录
.\venv\Scripts\python.exe src\retroarch_assistant.py ui
# 无控制台入口（系统的 pythonw 或虚拟环境 pythonw）
.\venv\Scripts\pythonw.exe src\desktop.py

# 测试与 JS 检查需要 Node.js（CI 使用 Node 22；最终用户无需安装）
python -m pip install -r requirements.txt pytest
python -m pytest -q -rs
python scripts/check_ui_js.py
python scripts/package_desktop.py --arch x64
# 已安装 Inno Setup 6 时生成安装程序
python scripts/package_desktop.py --arch x64 --installer
```

浏览器冒烟测试随 `pytest` 运行，也可以单独执行 `python -m pytest -q tests/python/test_browser_smoke.py`。需要 Node.js 22 或更新版本，以及 Chrome / Chromium；不需要 ChromeDriver 或额外 npm 依赖。测试在独立用户数据和浏览器配置目录内，使用离线名称样本及复制的列表，在 1440×900 和 1100×700 下完成“首页 → 打开本地库 → 切换主机 → 生成预览”，验证中文名称、关键控件可见性和无页面 JavaScript 异常，并检查列表文件未被改写。

默认自动查找浏览器，可用环境变量 `CHROME_BIN` 指定可执行文件的完整路径。未找到浏览器时会明确跳过；设置 `RETROARCH_ASSISTANT_REQUIRE_BROWSER=1` 则会失败，回归 CI 的 Ubuntu / Python 3.13 任务强制启用此检查。截图和日志保存在 `output/playwright/browser-smoke/`，失败时额外保存页面 HTML、截图及错误信息，CI 会上传该目录。

后端按领域拆分：`api_routes.py` 注册 GET / POST 路径，`api_library.py`、`api_playlists.py`、`api_artwork.py`、`api_tasks.py`、`api_data.py`、`api_desktop.py`、`api_config.py` 实现接口；`server.py` 负责同源会话、请求解析、静态资源及服务启动。处理函数接收请求、运行上下文和已解析的参数，配置路径与任务管理器始终由当前服务提供；新增接口应在路由表中显式注册。

`retroarch_assistant.py` 只处理 CLI 参数与分发，`playlist_service.py` 是统一公开入口，通过显式导出保留原有函数和提案类型；HTTP 与 CLI 使用同一核心，核心不依赖服务启动。内部职责如下：

- `playlist_analysis.py`：名称、ROM、DAT 证据分析与提案生成。
- `playlist_proposals.py`：提案数据结构、匹配元数据、标识及原始条目快照校验。
- `playlist_artwork.py`：只读查找本地／ADB 图片，供分析与游戏列表浏览复用。
- `playlist_writeback.py`：文件锁、汇总摘要校验、备份、写回、回读验证及图片任务。
- `playlist_batch.py`：原有 CLI 单列表和目录处理流程；HTTP 的“先汇总再确认”仍由 `batch_review.py` 管理。

只读图片查找和写回模块可以独立导入，不加载分析器或名称翻译器。修改依赖或测试替换点时，在实际拥有该依赖的模块操作，统一入口不再复制这些内部依赖。

`batch_review.py` 保存只读汇总所需的提案与文件摘要，`playlist_transport.py` 复用本地／ADB 写回协议；`job_manager.py` 管理任务状态，`job_results.py` 转换任务结果；原 `desktop_api.py` 已由上述领域模块替代。

macOS 在对应架构机器上执行 `python3 scripts/package_desktop.py --arch arm64` 或 `--arch x64`。脚本使用 onedir/app bundle，核对 Python 实际架构，并从临时工作目录启动 `--self-check` 验证资源和写入目录；不支持跨 OS 编译。Linux 继续保留 `retroarch_assistant.spec` 的 CLI 打包。

构建后可验证实际分发包（CI 对 Windows、macOS 两种架构均执行）：

```bash
python scripts/smoke_desktop_package.py --installer dist/RetroArchAssistant-Windows-x64-Setup.exe
python scripts/smoke_desktop_package.py --dmg dist/RetroArchAssistant-macOS-arm64.dmg
```

Windows 验收会静默安装到临时中文路径，运行程序后卸载，检查注册项清理和用户数据保留；若系统已有 PLCN 安装器注册项则拒绝运行，请使用干净测试机。macOS 会只读挂载 DMG，复制应用后卸载镜像，再启动复制出的程序。两者都验证资源、同配置重复启动、不同配置端口隔离和正常退出。所有用户数据使用临时 `RETROARCH_ASSISTANT_HOME`，不会修改日常配置。失败时日志目录保留并打印到终端。

便携版本可以使用 `--binary <可执行文件路径>` 做同样的程序验收。`RetroArchAssistant --no-browser` 可启动服务而不打开浏览器，供自动验收使用。这些检查不覆盖系统文件选择器、Gatekeeper、SmartScreen 或签名验收。

## 签名与正式发布

当前发布策略不购买签名证书，继续提供未签名、未公证产物。以下签名流程保留作未来参考，不属于当前实施范围。

桌面 CI 在 Windows x64、macOS Intel、Apple Silicon 上构建，产物明确命名为 `unsigned`。Tag 工作流只创建草稿预发布，保留 Linux CLI；不会直接发布未经人工验收的稳定版本。

macOS：将自己的 Developer ID Application 证书导入构建机器钥匙串，通过环境变量 `RETROARCH_ASSISTANT_CODESIGN_IDENTITY` 指定身份后重新构建。PyInstaller 会签署内部二进制，应用使用 `packaging/macos-entitlements.plist`；仍需检查 hardened runtime 和最终嵌套签名。构建后提交 DMG：

```bash
codesign --verify --deep --strict --verbose=2 'dist/RetroArch Assistant.app'
codesign -d --verbose=4 'dist/RetroArch Assistant.app'
xcrun notarytool submit dist/RetroArchAssistant-macOS-arm64.dmg --keychain-profile RetroArchAssistant-notary --wait
xcrun stapler staple dist/RetroArchAssistant-macOS-arm64.dmg
xcrun stapler validate dist/RetroArchAssistant-macOS-arm64.dmg
spctl --assess --type execute --verbose=4 'dist/RetroArch Assistant.app'
```

`RetroArchAssistant-notary` 是发布者自己事先配置的钥匙串 profile，占位名称不代表已存在凭据；Intel 产物同样处理。公证后从下载的 DMG 安装并检查 Gatekeeper、启动、文件选择和写回。不要仅因 CI 上自检成功就认为下载隔离环境也通过。

Windows：使用自己的代码签名证书和 Windows SDK `signtool` 签署 `dist/RetroArchAssistant/RetroArchAssistant.exe`，再生成安装程序和便携 ZIP，随后签署 Setup.exe，并用 `signtool verify /pa` 验证。证书密码只经发布环境/密钥库注入，不提交仓库。当前没有导入或申请任何签名证书。

正式发布前还需人工验收：安装/卸载与升级后配置保留、非 ASCII 路径、只读程序目录、双击重复启动、系统文件选择器、关闭/取消、恢复、真实 ADB 与外接卷断开。桌面 UI 的完整键盘/多语言检查继续保留为发布检查项。

首页会自动检测 USB 设备及默认 RetroArch 目录，展示可用、未授权和离线状态；检测不会自动打开游戏库。点击设备旁的“打开游戏库”后进入列表。“最近使用”保留最近 5 个成功打开的游戏库，显示具体路径与可用状态；历史继续保存在RetroArchAssistant 用户数据目录。也可使用“打开本地目录”或“手动输入路径”。检测或打开失败的原因会持续显示，可点击“重新检测”重试。点击顶部设备名称，在设备详情中选择“切换设备”可返回首页。

当多个 ROM 的列表名称映射到同一图片文件时，单项补图窗口会列出共用条目，并要求核对当前 ROM 的独立名称。确认后仅更新当前条目的名称、创建独立图片，并备份游戏列表；原共用图片和其他条目保持不变，其他类型图片复制到独立名称下。共用标签不再直接作为当前游戏英文名的识别依据。预览不写入设备，写入结果不确定时可使用原预览重试。

SNES 的“火焰之纹章3、4、5”等编号 ROM 名称分别识别为 Monshou no Nazo、Seisen no Keifu、Thracia 776，再自动搜索官方图库。此匹配来自名称别名，仍需核对候选图片与版本。空搜索词会提示输入名称，不发送无效图库请求。

批量图片下载遇到 404 时会查询官方图库目录，处理空格、语言标记和已知 PCE 标题别名的差异；地区、修订版和续作仍必须一致，多个候选无法唯一确定时保留失败结果。任务结束时分别显示列表写回和图片下载结果；图片失败会标记“部分完成”。

修复预览不再要求逐项人工确认。已识别名称和图片源的待处理条目默认勾选，可直接批量应用；无需修改的条目显示“无需修复”，缺少必要名称或图片源的条目显示“待补充”。匹配分数继续作为参考信息，编辑名称或图片源后可以直接应用。游戏列表的变更校验、备份和图片文件名冲突检查继续生效。

### RetroArch 与 PLCN 的图片一致性

RetroArch 1.20 读取本地缩略图时依次尝试 ROM 文件名、完整列表名称、去掉括号后缀的列表名称。PLCN 的游戏列表和图片预览使用同样的 ROM 文件名优先规则。单游戏更换图片时，如已有 ROM 文件名图片，会与列表名称图片一起更新并备份；如果该文件也被其他条目引用，会说明冲突并停止写入。写入中断可以重试，成功后重新读取设备列表，不再只替换页面中的临时图片。

更换图片窗口也可以修改未共用图片的游戏名称，避免拆分到最后一个条目后无法修正残留旧名。封面、游戏截图、标题图是三个独立类型，更换一个类型不会自动修复其他类型的内容；游戏列表的图片列用同样的三类名称与状态标签展示，三类标签保持一行，缩小缩略图后一屏可以多显示约三成游戏。每行的“补图 / 更换图片”在鼠标悬停或键盘聚焦时出现，减少整列重复按钮；需要时把指针移到该行即可。补图完成后结果以底部提示显示，不再占用顶部筛选栏。外部修改设备列表前先退出 RetroArch，完成后重新打开，让它重新加载列表和图片。

### 光盘游戏显示

PS、Saturn、Dreamcast 等光盘游戏常同时包含 `.cue` 描述文件和一个或多个 `.bin/.img` 数据文件。PLCN 在当前游戏列表和批量预览中把同一个碟的描述文件与附属数据合并成一条，优先选择 `.cue`、`.chd`、`.iso` 或 `.gdi`；附属数据文件仍保留在设备上，不会被删除。多碟游戏（`(Disc 1)`、`(Disc 2)`）在没有 `.m3u` 时每碟各显示一条，与 RetroArch 自身一致，切碟和每碟单独补图都保留；如果列表里有对应的 `.m3u`，则只显示 `.m3u` 这一条，它列出的碟文件不再重复出现。单独的 `.bin/.img` 没有被同组描述文件引用时会继续显示。

## 分发说明（v3.2.5 起）

Windows / macOS 包内置 Google Platform Tools 37.0.1 的 ADB 及必要依赖、NOTICE；不包含完整 Android SDK。构建时运行 `scripts/prepare_adb.py`，核验固定 SHA256，归档变化时构建失败，需维护者审核后更新校验值。

安装包自检直接调用内置 ADB 的 `version`，不依赖开发机 PATH。Windows 仍可能需要设备厂商 USB 驱动，Android 端必须授权 USB 调试。下载正确架构的 Release 附件即可双击启动；Source code 不属于安装包。

GitHub 自动构建目前没有配置发行签名凭据，Windows 包未签名，Mac 包只有构建所需的临时签名、未公证。本机存在 Developer ID 不代表 CI 已使用它。配置证书和公证凭据后，才能单独验证 Gatekeeper 的首次下载体验；不要把 CI 启动测试当作公证成功。


## macOS 文件传输运行库

源码运行及构建前执行 `brew install libmtp`。新的 macOS 应用包内置 libmtp/libusb 及许可证，Windows 本轮仍使用 ADB。

MTP 首次写回会在设备创建必要的图片目录；已有目标先保留 `.bak-…` 备份，暂存文件及最终文件均回读校验。传输过程中请保持连接；若设备会话无响应，重新插拔并选择“文件传输”，再点击“重新检测”。断线后的多文件操作可能部分完成，应查看任务结果并重新预览。


## 图片源与部分完成

SS 预览会检查官方封面、截图和标题图目录。名称唯一时自动匹配；地区/修订不明确时，游戏行提供“选择图片版本”下拉框，选择后再点击顶部确认应用。父目录识别的缩写只作为候选，例如 `DK2_SS` 需要核对候选后选择。多盘条目保留盘号，避免不同盘号覆盖同一图片。

名称写入后仍缺图片，会显示“名称完成 · 图片待补全”。网络失败可以重新选择应用，仅补图片；文件名冲突或图片源不匹配需先修正。当前任务已成功的 MTP 图片会复用；重复补图不再推送未改名的列表。

已选版本在成功应用后按当前列表/条目保存，下次预览复用。即使“修改名称”勾选着，只要所有已选名称都已相同，也只补图片，不重复写列表。

## 从游戏目录更新列表

打开掌机游戏库后点击左侧“更新游戏库”。没有现成列表时也可以进入设备，在主界面点击“更新游戏库”。

1. 选择游戏目录；首次指定主机。目录选择器直接浏览掌机存储，不要求映射为电脑磁盘。
2. 在“当前扫描配置”核对主机、默认核心、游戏来源及列表保存位置。需要修改时展开“扫描设置与高级选项”，确认推荐核心或更换候选。已有单项核心设置会保留。SS 推荐仅作为待真机验证的候选，MAME 必须指定匹配 ROM 集的 XML DAT。
3. 核对掌机中的实际游戏目录、已安装核心的完整路径；能从现有列表恢复时自动填入。选择目录后会查询已有列表，匹配到唯一主机及 Android 启动目录时自动填入；存在多个路径时才提供选择。MTP 地址不是 Android 启动路径，不能混用。私有核心目录无法通过 MTP 验证时显示“安装状态未知”；本地仅检查核心文件存在，不代表已验证加载运行。缺少路径或本地文件时会自动展开设置。
4. 缺少核心时展开官方下载入口，指定 **RetroArch 应用** 架构。使用 Libretro 官方 Buildbot 和官方 core-info，下载后检查 ELF 架构并记录 SHA-256。可传到掌机 `Download/RetroArchAssistant-cores`，再在 RetroArch 的“加载核心 → 安装或恢复核心”中安装，并更新核心信息文件；传输不等于安装。
5. 点击“开始扫描”会等待当前目录识别完成，完成后预览新增与保留项，确认后备份并增量更新 `.lpl`，随后可直接进入名称与图片补全预览。配置在更新成功后按设备、目录、主机保存。

扫描不会删除原条目或 ROM 文件，不覆盖已有单项中文名/核心信息。CUE/CHD/M3U 为光盘入口，M3U 已列出的分碟不重复新增，已有逐碟记录保留。ZIP/7z 首版按单个入口纳入，不检查包内内容或对大 ROM 全量计算 CRC。失效项删除、全库自动核心升级与 BIOS 下载不在本次功能中。

目录选择器中的“游戏所在存储”可在同一掌机的本机和存储卡间切换。它只选择 ROM 的来源位置：例如游戏位于 Games 存储卡，目标列表仍可保存在本机 RetroArch。首次跨存储扫描请核对“掌机中的实际游戏目录”，程序不会把另一存储的同名文件夹误当成挂载点。

若更新程序后 MTP 会话无法恢复，可先退出 RetroArch 助手，拔下 USB 等待约 5 秒，再连接、选择文件传输并保持解锁，最后启动 RetroArch 助手。应先让旧程序完全退出，再重连，避免旧会话仍在握手时重新占用设备。


### 预览中的身份与图片状态

修复预览在名称下显示匹配依据：精确名称、人工规则、数据库名称或校验值匹配、模糊候选、证据冲突、身份未识别。悬停查看证据与本地 Game ID。名称或封面推荐不代表已经验证 ROM 地区、修订及内容。

模糊、冲突与未识别项默认留待核对；可编辑名称或点击“采用此名称”，再与其他所选项一起确认应用。单独更换图片不自动确认候选游戏名称；“记住修正”仍用于保存本地规则。全部主机一键补全也会跳过这些待核对项。

图片标签区分“已有图片”“可补全”“待选择版本”“未匹配图片源”“图库查询失败”和“名称未识别”。“未匹配图片源”只表示当前查询没有找到合适源，不代表官方图库缺少这款游戏。“图片待处理”筛选包含版本待选、未识别、缺源和失败项；仅修改名称时不统计图片问题。

摘要随选择和当前处理选项同步变化，显示本次修改名称、补图及待处理项。扫描预览另显示新增、保留和跳过项，明确此次仅更新列表；名称图片尚未分析时不显示虚假的完成数。扫描和修复各自只确认其已展示的方案，不会隐式转换或移动游戏文件。


### 多盘与引用检查（阶段 2A）

选择 Saturn 或 PlayStation 列表后，点击游戏列表工具栏的“多盘与引用检查”。这是只读的分组视图，分别统计游戏组、光盘、关联文件及原列表入口；不会把候选组写回列表。

展开已有 M3U，可按原引用顺序查看各盘。展开候选组，可查看明确盘号、文件格式、体积、原入口、单项核心，以及已经保存的分盘图片源。“全部文件与引用”还会列出 CUE 音轨及其他列表对同一文件的引用。

检查会提示缺盘号、重复盘号、缺失文件、不同地区／修订／汉化标记、附赠盘、循环引用、组内核心差异和共享引用。版本差异依据文件名标记，不代表已经鉴定 ROM 内容。未声明总盘数时，只能发现已知盘号范围中的缺口，不能证明最后一盘之后没有缺盘。

MTP 使用已保存扫描配置中的 Android 目录与传输目录映射；找不到唯一映射时显示“尚未检查”，不会显示“文件缺失”。可关闭检查，在“更新游戏库”中核对并保存该目录配置，再重新检查。本轮不猜存储卡挂载点。

引用范围是当前列表所在目录内的 `.lpl`，未递归其他列表目录；读取失败会显示在覆盖范围中。这些结果不能直接作为删除文件的依据。检查本身不写入；阶段 2B 可从组详情打开“编辑 M3U 方案”，选择盘序并预览后确认应用。支持仅保存 M3U，或在核心与存档检查通过后更新当前列表；原光盘与存档保留。支持范围和待处理条件见 [M3U 操作契约](M3U_OPERATIONS.md)，实际核心运行和换盘仍待真机验收。


### 存储优化：电脑 CHD 副本

选中 Saturn／PlayStation 列表后点击左侧“存储优化”，指定电脑工作目录与本机 chdman，先分析工具、空间、核心声明及输入条件，再确认所选光盘。首版支持 BINARY 2352 扇区 CUE，执行 CHD 完整性和逐轨解压回读比对；原文件与启动引用保留，不回传掌机。压缩比例在完成前未知，保留源文件时掌机释放空间为 0。

取消会保留已验证输出，不发布未完成 CHD。支持范围、空间预算、工具来源和实际运行待验收条件见 [CHD 本地转换契约](CHD_LOCAL_CONVERSION.md)。


### CHD 回传、替换与恢复

转换完成后点击“预览回传／替换方案”，默认只回传副本。更新引用需要核对原核心版本并报告启动、游戏内存档及所需换盘验证；清理还须确认检查目录包含全部相关引用。预览明确目标、电脑备份、待修改列表／M3U、可移除文件与保留的共享音轨。

恢复会先还原原镜像再还原引用，原文件变化或备份损坏时停止覆盖；CHD 获得新引用时保留并显示原因。详见 [CHD 回传与恢复契约](CHD_DEPLOYMENT_AND_RECOVERY.md)。MTP 原生真机与实际游戏运行仍待验收。


### 目录整理与卡带 ZIP 副本

选择一台主机列表后，点击左侧“目录整理与 ROM 压缩”。选择游戏源目录和主机目标目录，即可预览平铺候选、重名冲突与需要保留目录的例外。本机和存储卡可分别浏览。分析保持只读；勾选候选后点击“预览目录整理”，可单独预览复制、引用更新或有备份的移动。

已核对 mGBA／Gambatte／Snes9x 的普通卡带 ROM 可勾选生成电脑 ZIP 副本；电脑工作目录留空时使用应用数据目录。ZIP 解压内容逐字节验证。生成电脑副本时保留设备原文件与列表，掌机节省空间为 0。完成后可点击“预览 ZIP 回传／替换”，默认仍仅复制；切换与清理需核对存档设置和运行报告。详见 [阶段 4A 契约](ROM_LAYOUT_AND_ZIP_COPIES.md)。


### 执行目录整理与恢复

先仅复制到目标目录，在 RetroArch 中验证目标文件、存档与多盘换盘，再重新预览更新引用或移动。目标冲突不会被覆盖；未转换的 CUE＋BIN 等多文件游戏保持目录关系。当前自动切换仅支持明确的固定全局存档目录，未知设置可仅复制。

仍被新列表或 M3U 使用的输出会保留。空目录与原存档不清理。详见 [目录整理与恢复契约](ROM_RELOCATION_AND_RECOVERY.md)。

## 首页资料状态与就地操作

游戏库概览按当前存储范围显示缺图数量，以及“尚未使用中文名”的数量。后者只检查现有显示名称是否包含汉字，不联网查询名称库，也不表示一定有可用译名；英文原名、数字名和纯假名都计入该统计，含汉字的名称不再计入。状态条在任一数量大于零时显示。


在游戏列表中打开右侧详情，点击“更换封面”，可直接在详情栏搜索官方或备用图库、导入本地图片、选择图片类型并对比候选，确认后才写入。切换游戏会退出未提交的图片编辑；提交写入后需等待任务结果。人工核对预览中的补图入口仍使用独立弹窗，保留预览上下文。

添加游戏页面的导入按钮会持续显示；未选来源、分析中、存在冲突或缺少启动目录时保持禁用，并在底部操作栏说明原因。MTP 导入会先尝试从现有列表识别掌机实际启动目录，无法确定时展开目标设置并定位到该字段。请填写 RetroArch 中的 Android 路径（例如 `/storage/卡号/Roms/MD`），不要填写 `mtp://` 传输地址；补齐后会重新分析并在方案有效时启用导入。

MTP 导入的复制位置与 Android 启动路径必须对应同一存储及相同目录。已有扫描映射能够确定存储卡卷号时，程序会拒绝不一致的目录组合。某主机尚无导入配置时，先明确选择掌机目标目录，不再默认写入 RetroArch 所在存储；切换复制目录会清空旧启动路径，重新识别或填写后再分析。

### 导入路径与失败恢复

导入预览明确区分本地路径、与已保存映射一致、手动配置、待核对；冲突会直接报错。没有已知映射的 MTP 目录不能导入，也不会读取或写入目标 ROM。可直接在本页核对并保存启动位置，再重新分析。与已保存配置一致或经过手动核对都不代表已验证核心加载或游戏启动。

掌机目标摘要使用存储名称与相对目录，MTP 地址保留在内部字段，不作为用户可编辑的复制位置。预览与完成结果分别统计新增列表条目、复制文件、复用、跳过与失败；已有列表条目补回缺失文件时会显示复制数量，不再仅显示“导入 0 个游戏”。

失败后可点击“重新分析”重新核对当前来源和目标，也可“重新连接”恢复本地会话与设备发现。两者保留当前文件选择；本地服务重启丢失旧任务记录时明确提示结果未知。连接中断不会自动重发可能已经写入的请求，先查看任务和目标文件后再分析。被明确以 403 拒绝的请求可在恢复会话后重试一次。

### 简化后的导入页面

“添加游戏”只负责从电脑复制；“扫描掌机游戏”在游戏库标题栏单独进入。导入页按“选择游戏 → 确认位置 → 导入结果”组织，文件很多时先显示前六项，完整列表可展开；文件来源支持单项移除和清空。

主机和位置摘要始终可见，目录及列表文件名等设置按需展开。默认复用该主机最近一次导入使用的位置。首次映射未知时，直接在本页核对并保存启动位置，不清除文件选择；必须明确勾选已在掌机核对，且所选目录和 Android 路径的相对目录一致。配置标记为手动来源，显示“启动未验证”，不宣称程序验证了挂载点或核心运行。已有映射冲突仍拒绝保存。保存配置前保留本地配置备份，不移动或删除 ROM。

确认按钮显示游戏数；只补回缺失文件时显示文件数。正常状态收起重新分析和连接按钮，出错时再显示。完成页分别报告复制及列表更新结果，提供“查看游戏”“补全名称与封面”“继续添加”；补全作用于刚导入的主机，不自动处理整个游戏库。

### 更新一个 ROM

打开游戏右侧详情，点击“更新 ROM”，选择电脑上的新版文件，再点击“更新”。程序保留原文件名和启动路径，自动备份旧 ROM、替换并读回校验；名称、图片、核心与存档文件保留。旧内容校验值失效时将列表 CRC 重置为 DETECT。更新前退出 RetroArch，避免它覆盖列表；存档文件保留不等于新旧 ROM 的存档兼容性已经验证。

首版支持列入支持范围的未压缩单文件卡带 ROM，文件格式须与原文件相同，新旧文件均不超过 64 MiB；多文件光盘、压缩包和未知路径不通过此入口替换。不可更新时按钮禁用并说明原因，内容相同则提示无需更新。

完成后详情提供“恢复旧版 ROM”，重开应用仍可找到。更新失败会尝试恢复旧版，无法自动恢复时保留日志与备份供恢复；恢复前核对摘要，后续被其它操作修改的 ROM 不会被强行覆盖。更新方案使用选择文件时读取并展示的内容，不会在确认后悄悄读取另一份新版。

从添加游戏选择到已在列表中的同名冲突文件时，可点击“更新已有游戏 ROM”，直接打开同一更新流程；不会以普通导入覆盖冲突。
