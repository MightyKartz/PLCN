# CHD 拉取、回传、引用更新与恢复（阶段 3B）

实施日期：2026-11-16。依赖阶段 3A。原文件清理必须通过具体方案确认；本次开发验证仅使用合成光盘与受控 MTP，不连接真实掌机。

## 用户流程

1. 在“存储优化”中分析并选择光盘。本地文件沿用 3A 流程；MTP 光盘先显示可访问路径、引用文件与体积，确认后才拉取完整源到电脑。拉取前不声称已证明镜像可转换。
2. 电脑执行 CHD 转换、完整性和逐轨内容验证。MTP 原 CUE／音轨保存在 `PLCN-SOURCES-<转换 ID>`，工作镜像仅指向这些已拉取文件，不让 chdman 沿设备路径访问额外文件。
3. 从转换结果或“设置 → 任务与恢复 → 电脑 CHD 转换”打开“预览回传／替换方案”。默认选中“仅回传”。
4. 选择具体输出与执行方式，预览目标路径、引用修改、可移除源、保留的共享文件、递归检查目录及空间预算。
5. 确认方案后执行。运行中可以取消，断线后查看持久记录，选择“核对后继续”或“恢复原镜像与引用”。

| 方式 | 行为 |
| --- | --- |
| 仅回传 | 在原 CUE 旁创建同基础名 CHD；保留原文件与全部引用，不要求运行报告 |
| 回传并更新引用 | 创建 CHD，备份并更新已检查的 Playlist／M3U，保留原文件 |
| 回传、更新引用并清理 | 完成上传、回读、引用核对后，仅清理已有完整电脑备份且无其他已知引用的源文件 |

“仅回传”不会额外复制整份原镜像做部署备份：它不修改源文件，恢复时也不改源文件。会保留 CHD 输出副本用于继续任务。涉及引用更新的两种模式保存完整原镜像和 CHD 备份。

## 核心与运行报告

更新引用要求受影响入口使用同一已核对的核心，官方 core-info 声明支持 CHD，并由用户填写实际核心版本，明确报告已用这些输出验证启动、游戏内存档与所需换盘。程序绑定转换结果的 SHA-256、核心路径、报告版本与操作时间。

报告来源标记为 `user_reported`。MTP 无法独立核实应用私有目录中的核心安装和版本；勾选报告不等于软件已实际启动游戏。未知核心、多个不同核心或缺少报告时阻止更新／清理，不自动更换或升级核心。

同基础名 CUE → CHD 保留原目录和启动基础名；既有 M3U 仅替换盘引用，名称和盘序保留。本流程不改存档、即时存档、BIOS 或核心文件，也不宣称即时存档跨格式兼容。确认执行前退出 RetroArch；若实际核心或进度配置变化，应重新核对报告。

## 引用检查范围

递归检查所选 CUE／音轨所在目录及原列表目录，预览逐项列出实际根目录。扫描 `.lpl/.m3u/.cue` 的引用，读取元数据上限 1 MiB；`.ccd/.toc/.gdi`、损坏或无法映射的描述进入未知项。电脑工具自有的 `PLCN-SOURCES-/PLCN-CHD-/PLCN-DEPLOY-` 目录不作为游戏引用目录；不遍历符号链接。

- 检查并更新范围内的所有相关列表，包括当前未显示的同目录列表和独立 M3U。
- 根据确认过的扫描配置转换 Android 路径与 MTP 地址，允许 ROM 与列表分属同一掌机的不同存储；不从 MTP 存储编号猜测 Android 卡挂载路径。
- 同一音轨仍被未选中的 CUE、列表或其他描述引用时保留；不能因为一个 CUE 已转换就删除共享 BIN。
- 已知新引用、目录变化或描述文件变化会使旧方案停止。未知描述阻止更新／清理；仅回传可以保留原引用继续使用。
- 清理还要求用户确认上述目录包含全部相关引用。检查不覆盖整个电脑／掌机，范围外、其他格式或符号链接中的引用无法得到全局不存在证明；不能确认时选“保留原文件”。

M3U 相对引用继续使用相对路径；列表的新入口使用实际启动路径，保留其他条目字段、人工名称及核心设置。原 Disc／Game 标识迁移到新入口，旧 Content 记录保留；确认组的成员、原分盘条目和人工图片选择相应延续，恢复使用本操作涉及的键，不回滚无关元数据。

## 大文件传输与空间

新增 libmtp 文件级下载与上传接口：数据写入电脑私有文件，以约 1 MiB 块计算 SHA-256，不通过旧的 `read()/write()` 将整盘载入 Python 内存。libmtp 的进度回调可以请求取消，回调中的 Python 异常在原生调用返回后重新抛出，不静默丢失。

上传只创建新文件：暂存 → 完整回读 SHA-256 → 改为目标名 → 再次完整回读。已有相同目标可复用且恢复时不删除；已有不同目标、大小写冲突或来源变化阻止执行，不强制覆盖。

预算按真实存储卷合并，避免同一存储不同目录分别通过却合计不足：

- 目标卷：新增 CHD 与元数据暂存所需空间，不提前把预计删除源算作可用空间。
- 电脑备份卷：本模式需要的原镜像与 CHD 副本。
- 应用数据卷：引用前后快照；回读临时卷：最大镜像文件空间。
- 每卷保留 64 MiB 余量。执行和继续前再次检查，恢复先检查重建源和引用需要的空间。

电脑备份与本地源在同卷时，整个卷可用空间可能减少。预览的“镜像空间净变化”仅计算计划移除镜像减去新增 CHD，不包含电脑备份、元数据备份和其他程序的磁盘活动。任务完成后根据已核对的逐文件状态报告执行时的镜像净变化；部分完成显示未知，不把计划值当作已释放空间。

## 持久事务顺序

电脑数据目录 `chd-deployments/<操作 ID>/manifest.json` 保存已确认方案、固定目标／暂存路径、源与输出指纹、运行报告、引用范围、空间预算及真实步骤。镜像备份位于预览中的 `PLCN-DEPLOY-<操作 ID>`；引用快照和索引变更复用阶段 2B 事务。

顺序如下：

1. 保存方案，再创建并核对本模式需要的电脑备份；已完成的备份继续时不重复拉取。
2. 再核对来源及检查范围，上传并回读 CHD。
3. 更新引用前重新检查源，按预览备份和写入 Playlist／M3U，并回读核对。
4. 清理前再次核对目标 CHD、引用必须保持新内容、原镜像电脑备份和当前源指纹。
5. 仅移除方案中可清理、无其他引用的源；逐文件记录“准备移除／已移除”。

MTP 多文件更新不是原子操作。取消或断开显示“部分完成”，不会冒充成功。继续时校验电脑备份、现有目标、原始身份／图片来源键、引用内容和完成状态；上传改名或源删除后断开可识别已完成步骤，避免重复上传或删除。

## 恢复顺序与停止条件

涉及引用修改时，先恢复缺失的原镜像并回读，再还原列表／M3U 与身份关联，最后移除本次新建、内容未变化且没有新引用的 CHD。仅回传的恢复不写原镜像。

- 原路径出现不同文件、目标 CHD 被外部修改、电脑备份损坏、空间不足或相关索引变化时停止覆盖，显示待处理状态。
- 恢复时若新增引用仍使用 CHD，或新的未知描述使引用无法证明完整，则保留该 CHD，记录保留原因；不破坏后来新增的引用。
- 完整且已校验的暂存可以继续改名；中断留下的未知／部分暂存不自动覆盖或删除，需核对暂存路径与备份后处理。
- 引用子事务从普通 M3U 恢复列表中隐藏，普通 M3U 恢复 API 也拒绝单独恢复它，避免原镜像仍缺失时先把引用指回原文件。
- 不清理电脑备份或元数据设备备份，不猜测断电后残留文件。应用重启后的记录会保留可审查状态；没有“无条件强制覆盖”。

## 服务端与界面状态契约

- `POST /api/chd/deployment/preview` 生成只读预览，实际方案保留在服务端。
- `POST /api/chd/deployment/apply` 只接受一次性 `preview_job_id`，忽略客户端伪造的目标、删除集合或模式。
- `POST /api/chd/deployment/recover` 只接受持久操作 ID 与 `resume/restore`。
- 转换 ID、选盘、模式、版本报告、范围确认或当前游戏库变化后旧预览失效；旧响应不能启用确认按钮。SSE 重连保持操作锁，不重发写入。
- 预览就绪后折叠设置，优先展示实际变更、备份和检查范围。恢复与运行读取相同的操作记录，不把旧计划投影成实际完成结果。

本阶段同时修复快速关闭并重开设置时，旧 `close` 事件废弃新请求而使任务页空白的问题；以当前弹窗开放状态和请求版本判断事件归属，新增运行态回归。

## 验证与待验收

完整回归 385 项通过；新增部署状态与弹窗归属 Node 测试 5 项通过；JavaScript 语法检查通过（16 个脚本、98 个事件处理器）。Python 编译与 diff 检查通过，仅有既存的 urllib3／LibreSSL 环境警告。

自动样例覆盖本地与受控 MTP 的拉取、转换、上传、回读、引用切换、共享音轨保留、清理与恢复；包括上传改名后断开、清理后断开、备份中断、取消、源变化、索引变化、元数据回退、备份损坏、外部目标变化、新引用保留输出及服务端方案单次消费。原生边界样例覆盖 libmtp 文件级接口、暂存改名、完整回读与回调取消；还验证确认 M3U 组的原光盘标识与分盘快照迁移，以及引用快照准备中断后的重建继续。

真实浏览器以临时本地服务在 1100×700／1440×900 验证副本默认值、只读预览、合成样例运行报告、替换与恢复、持久任务展示和设置快速重开。测试中的运行报告是合成流程样例，不是掌机验收证据。

本轮没有重启日常 7777 服务，也没有连接、写入或清理真实掌机。仍待真机验证：双存储、大文件取消／重连、实际 CHD 启动与换盘、游戏内存档衔接、固件的暂存与恢复表现。MTP 原生接入仍限现有 macOS libmtp 实现；其他平台支持本地文件流程。下一项阶段 4：主机目录整理、冲突处理与经过核对的更多压缩格式。
