# CHD 能力检查、空间分析与电脑转换（阶段 3A）

实施日期：2026-11-16。依赖阶段 2B；本阶段仅在电脑生成新副本，不执行阶段 3B 的设备拉取／回传、引用更新、备份替换或源文件清理。

## 用户流程与界面

进入游戏库，选中 Saturn／PlayStation 列表，打开左侧“存储优化”。选择电脑工作目录，或使用应用数据目录；chdman 默认从 PATH 查找，也可以通过不限制 `.lpl` 的程序选择器指定本机可执行文件。

点击“分析空间与工具”后，显示：

- 关联文件已知体积、可转换源文件的去重体积；已有 CHD 和不支持文件的跳过原因。
- 当前电脑可用空间与保守工作空间预算；压缩比例暂为未知，不承诺固定比例。
- 每个可转换光盘的源路径、输出文件名、当前核心的官方 CHD 格式声明与未知状态、共享源文件。
- 确认前固定的 `PLCN-CHD-<方案 ID>` 输出目录。工具版本、路径、来源待核对及引用覆盖范围在可展开详情中说明。

分析完成后折叠目录／工具设置，主区域展示结果。用户选择光盘，再点击“确认仅在电脑转换”。修改工具、工作目录或当前列表会使方案失效；晚到的旧分析不会启用转换。服务端方案只能消费一次，不接受客户端替换源路径、输出目录或工具路径。

完成后直接展示输出及实际大小，在“设置 → 任务与恢复 → 电脑 CHD 转换”查看持久记录。保留原文件意味着本轮掌机实际释放空间为 **0**；输入与输出的体积差不能算作已回收空间。

## 能力边界

首版转换对象为 Saturn／PlayStation 列表及其 M3U 引用下的本地 CUE，采用明确可比对的输入子集：

- UTF-8（含 BOM）CUE，描述文件不超过 1 MiB。
- FILE BINARY 引用现存 `.bin/.img/.raw`，每个文件由完整的 2352 字节扇区构成。
- TRACK 编号从 1 连续排列，类型为 `MODE1/2352`、`MODE2/2352` 或 `AUDIO`。
- 支持 INDEX 00／01、PREGAP／POSTGAP，验证轨道边界、文件开头未引用数据、每个文件的轨道覆盖；忽略说明性 REM。
- 单文件多音轨、多个音轨文件、多个光盘及共享音轨可以分析／转换；共享源文件统计去重，始终保留。

不支持的 CUE 声明（如 FLAGS、INDEX 02、WAVE）、2048 扇区输入、ISO／CCD／TOC／GDI、未知边界或缺少引用显示待处理，不声称已验证无损。已有 CHD／压缩包不重复压缩；其他主机和卡带 ROM 压缩留待后续阶段。MTP 本轮可显示检查结果与已知体积，但不能启动远程镜像转换，不读取完整远程 ROM。

沿用原入口核心，包括经 M3U 到达光盘的入口；复用官方 core-info 查询 CHD 声明，按核心分别展示。工具版本确定，核心安装版本及实际加载仍是未知。核心未声明或无法识别时允许生成独立电脑副本，并明确提示；不允许据此切换入口，不下载或更换核心。

## 工具与来源

使用本机 MAME chdman；识别版本及 `createcd/verify/extractcd` 能力，保存可执行文件 SHA-256，执行前再次核对工具是否变化。用户指定的二进制来源仍标记为未验证，程序名称和 SHA-256 不证明官方来源。

本阶段不随应用分发或自动下载工具。界面提供 [MAME 官方发行入口](https://www.mamedev.org/release.html)，开发与 CI 使用系统安装的 MAME 工具；今后若分发二进制须另行核对对应构建、依赖及许可证，参见 [MAME 官方许可说明](https://github.com/mamedev/mame/blob/master/COPYING)。

运行采用参数数组、不使用 shell、不传强制覆盖或 verify 修复参数。首版固定单转换进程、`-np 1`，使用所记录工具的 CD 默认压缩设置，避免多盘同时挤占电脑空间和 CPU。

## 分析与空间预算

分析在后台流式读取本地候选源文件 SHA-256，保持约 1 MiB 读取块，支持取消；源 CUE 和音轨按实际路径去重。读取时检查大小和修改时间变化。不会把名称匹配、文件存在性或元数据检查等同于镜像内容验证。

设所选每盘 CUE 与音轨体积为 `S_i`，预算为：

```text
2 × sum(S_i) + 3 × max(S_i) + 64 MiB
```

其中为保留的 CHD 输出和解压回读预留扩张余量，再加一份当前源快照。这个数是工作空间预算，不是压缩大小预测；共享输入在源体积统计中去重，在逐盘输出预算中保守重复计入。勾选变化时按所选集合更新预算；即使整批放不下，也可减少所选光盘。确认执行时服务端重新检查当前可用空间；空间不足时不开始转换。外部程序后来耗尽磁盘仍可能使任务失败，但不修改原文件。

输出和临时目录位于同一电脑工作卷。设备目标空间、上传暂存与电脑备份需求在阶段 3B 检查，本轮不以猜测的设备空间启用替换。

## 验证顺序

每个光盘按顺序执行：

1. 将已确认的源 CUE／音轨流式复制到独立临时目录，与分析时保存的全文件 SHA-256 比较；不直接对用户原文件执行转换。
2. 按支持的 CUE 语法生成只指向临时音轨的输入描述；相对引用与父目录文件不会使 chdman 读取用户目录中的其他未确认文件。
3. `createcd` 生成临时 CHD，记录命令日志。
4. `verify` 检查 CHD 内部完整性；不使用 `--fix`。
5. `extractcd` 解压到本次临时目录，重新解析 CUE；逐轨比较轨号、类型、数据字节长度、INDEX 01 相对位置、声明型间隙和包含存储型间隙的扇区 SHA-256。
6. 再次读取原文件指纹，确认转换期间源未变化。核对通过后才把 CHD 发布到预览中的输出文件名；保存 CHD SHA-256、实际体积和验证证据。

这套内容核对是对所支持 CUE 子集的扇区与轨道结构证明，不是原 CUE 文本逐字还原，也不验证未支持的子通道／控制信息。不能据此证明原盘没有损坏，更不证明实际核心可启动、汉化内容正常、换盘成功或存档兼容。结果分别记录 `content_verified` 与 `runtime_status: not_tested`，不会把两者合并成“可以替换”。

## 取消、失败与历史

电脑数据目录的 `chd-operations/<操作 ID>/manifest.json` 在转换前建立，记录来源指纹、固定工具、输出目录和逐盘真实结果。工作卷的独立输出目录不会覆盖用户现有 CHD。

任务支持在文件流读取与子进程等待期间取消。取消时终止本任务 chdman，等待退出后清理本任务临时文件；未通过全部检查的 CHD 不发布。已完成并有内容验证记录的前序光盘保留，历史显示“已取消／失败”及已验证数量。日志保留在输出目录，原光盘、列表、M3U、核心与存档均不修改。

网络重连不重复提交；应用重启后可从电脑清单看到结果。进程异常终止留下的 `running` 记录显示“运行中／中断，请核对”，不冒充完成。3A 不提供自动续跑、引用恢复或自动清理；需要重新分析并生成新的独立输出目录。突然断电时临时目录可能遗留，需核对记录后手动处理，不对用户文件执行推断性清理。
