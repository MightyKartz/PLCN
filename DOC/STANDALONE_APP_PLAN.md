# RetroArch 助手三端应用计划

macOS 和 Windows 沿用完整工作台。Android 首版管理掌机本机的游戏库。HTML、CSS 和 JavaScript 随应用打包，Python 业务规则按平台能力复用。现有 CLI 继续支持脚本、批处理和数据迁移。

当前游戏库基线为 PR #49。依赖它的 PR 使用叠加分支，前序 PR 合并后将后续 PR 切到适当的主分支基线。

| PR | 范围 | 合入前验证 |
|---|---|---|
| 1 · 本地服务生命周期 | 让浏览器入口和独立窗口能够使用同一套监听器、实例锁与任务退出规则 | 浏览器、CLI 和无界面入口保持可用。退出先释放设备会话，再释放实例锁 |
| 2 · 桌面独立窗口预览 | macOS WKWebView、Windows WebView2。沿用打包和本地 API，先通过显式参数启用 | macOS 和 Windows 安装后可渲染工作台、完成目录选择、重复启动唤回窗口、空闲时退出。活动写入任务期间拒绝退出 |
| 3 · 桌面默认入口与发行 | 将独立窗口设为默认，保留显式浏览器入口。补齐安装、升级及发行说明，配置发行签名 | macOS Apple Silicon / Intel 与 Windows x64 干净安装、升级保留用户数据。覆盖外接盘、ADB，以及 macOS MTP 实机流程 |
| 4 · Android 真机可行性 | Kotlin 目录授权与文件访问，Android WebView 加载内置前端。验证 Chaquopy 和核心 Python 依赖 | ARM64 掌机对内置共享目录和 SD 卡分别验证重启后授权、读取、预览、备份、写入和读回。使用 RetroArch 验证列表和实际游戏启动 |
| 5 · Android 首个可用 APK | 在经过验证的共享目录上提供库浏览、扫描、名称与封面补全。增加触屏和掌机按键所需的导航 | 真机完成授权、预览和应用。取消、应用重启、授权撤销后的结果清楚可查。签名 APK 可覆盖安装 |
| 6 · 按能力扩展掌机操作 | 在存储行为已验证的设备上逐步加入导入、ROM 替换和恢复。单独评估 CHD 工具链 | 所支持的目录提供者能完成对应操作的暂存、备份、读回或恢复。能力不足时在预览阶段给出提示 |

PR 4 的验证与桌面窗口开发可以并行。Android 存储访问使用系统目录授权，RetroArch 启动路径依据现有列表或真机配置单独核对。Android 的目录 URI、桌面传输地址与 RetroArch 启动路径各有用途。先验证一条完整的读写路径，再根据实测提取可共享的存储接口。平台包沿用既有 GitHub Actions 发行方式，各 PR 以内测产物进行验收。
