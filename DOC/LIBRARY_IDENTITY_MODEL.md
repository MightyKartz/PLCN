# 游戏库标识与读取模型（阶段 1A）

状态：第一阶段的首个实现 PR。尚未完成整个第一阶段，也未新增多盘分组、M3U 生成或文件移动能力。

## 标识规则

- `game_id`、`disc_id`、`content_id` 使用随机 UUID，持久化在当前 PLCN 用户目录的 `library-identities.json`。
- 文件路径用于查找既有绑定，UUID 本身不由中文名、路径或条目序号计算。
- 首次读取旧列表时，在电脑本地建立绑定，不向 `.lpl` 增加自定义字段，不改写掌机列表、游戏文件或图片。
- 同一列表中路径相同的重复行保留原始索引，并关联同一个游戏和文件。不同路径即使中文名相同，也分配不同标识。
- 同一个列表目录内，不同列表引用完全相同的文件路径时共享 `content_id`，各自保留游戏入口及单项核心配置。不同设备或列表目录的标识相互隔离。
- 改显示名、调整顺序或修改核心不会改变绑定。删除后重新加入同一位置的条目复用绑定；索引暂不自动清理。
- 不用模糊匹配、中文同名或相同 CRC 合并身份。此标识表示 PLCN 本地管理对象，不代表已验证 ROM 的官方版本。

## API 兼容性

`GET /api/playlist/items` 保留原响应字段，新增：

- 每个浏览条目的 `game_id`、`disc_id`、`content_id`。
- 顶层 `library_model`：`version`、`scope`、`games`、`discs`、`contents`、`entries`。

`entries` 按原始 `.lpl` 索引排列，保留全部行和各行核心配置；既有浏览器隐藏同盘重复描述文件的逻辑不改变。显示层的索引仍可用于现有编辑／应用接口，当前 PR 不改变写回契约。

`games` 表示当前独立启动入口，尚未把两张盘归成一个游戏。`discs` 仅识别 Saturn / PlayStation 的明确光盘入口格式，盘号只依据文件名中的明确标记；没有标记则返回 `null` 和 `number_source: unknown`。M3U、单独 BIN 音轨、MAME 的 CHD 不凭扩展名伪造光盘记录。M3U 内部引用留待阶段二解析。

`contents` 记录当前列表声明的路径和格式，并不代表程序已经检查文件存在、读取全部内容或验证了体积与摘要。设备内 Android 启动路径不会被转换为电脑本地路径。

## 本地元数据边界

- 读取列表仅可能初始化／补充电脑本地的标识索引；不会写入原列表或设备。
- 已有绑定的重复读取不重写索引。
- 同一进程的并发读取串行更新索引，持久化复用现有文件锁和原子 JSON 写入。
- 损坏索引或未知版本明确报错，保留原文件，不静默重新分配标识。
- 手工删除用户元数据后，下一次读取会生成新标识。该索引应纳入后续“任务与恢复”的备份范围。

## 尚未交付的路径迁移契约

路径移动、格式转换、列表文件改名和跨设备复制不能靠扫描自动证明属于原对象。本 PR 不宣称这些操作后的标识已经可自动延续。

后续操作 PR 必须在服务端已确认的变更方案中记录旧标识、旧绑定和新绑定，验证目标后再更新绑定；不能通过相似文件名猜测。多盘合并还需保留原分盘标识与游戏组的关联，不能删除原身份后重新生成全部 UUID。

现有图片选择／人工覆盖仍使用原机制。本 PR 保留这些数据，尚未将它们迁移到 UUID；实际迁移应与多盘和路径变更操作一起完成，并有回归检查。

## 验证范围

自动检查覆盖旧列表只读迁移、中文改名／排序／核心变化后标识稳定、同名分盘隔离、跨设备与平台隔离、M3U／音轨／街机 CHD 不误判、并发读取、重复读取不写索引、损坏索引不覆盖。集成检查继续覆盖本地、ADB、MTP 的现有列表读取接口。

本轮本地验证：完整回归 285 项通过（包含浏览器流程），JavaScript 语法、Python 编译与 diff 空白检查通过。真机多盘操作不属于本 PR 范围。
