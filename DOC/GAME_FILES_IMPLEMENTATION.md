# 游戏文件实施计划

设计依据为 RetroArch 助手 UI 基准和已确认的 HTML 原型。沿用现有工作台的颜色、主题和控件。目录页以文件名为主，复制结果放在底部，改名和删除的影响在操作时显示。

## 1. 目录浏览

在主工作区提供「游戏文件」，替换原「添加游戏」入口。文件页的「添加文件」沿用现有导入流程。打开设备或本地游戏库后可从工具栏进入文件页。支持本地目录、直接挂载的 SD 卡和 USB 文件传输存储。设备目录发现直接读取存储，允许从根目录进入任意自定义子目录。验收使用有列表和空库两种场景，包括目录不可访问时的错误提示。

已接入游戏库工作台，目录页可只读浏览。Chrome 已覆盖本地目录及没有播放列表的模拟 MTP 存储。USB 硬件验收归入第 5 步。

## 2. 复制文件

在 macOS 桌面窗口验证从访达拖入多文件时，应用能够取得可信且可读取的源文件。保留原生选择文件入口。在本地和 MTP 上预览冲突并使用后台任务复制，同名默认跳过，展示逐文件结果。复制成功后刷新当前目录。验收包括取消、传输断开及部分成功。

## 3. 加入或创建播放列表

为设备和存储保存 ROM 目录、主机、Android 启动目录及具体列表目标。缺少列表时允许确认 RetroArch 生效的播放列表目录并预览首份列表。已有配置直接纳入扫描，包括自定义目录。只提交复制成功的游戏入口，单独重试列表写入。用实际掌机从新列表启动一个 ROM 验收。

## 4. 改名与删除

优先覆盖单文件 ROM。改名同步更新已知启动路径，并保留显示名、核心和封面。删除前展示受影响的条目、独占文件和共享文件。默认保留封面及存档，只有确认当前游戏库中没有其他条目使用的封面才可选清理。删除前在电脑上备份文件并记录原路径。加入 CUE 和 M3U 引用检查前，限制有共享依赖或引用不明确的操作。验收覆盖文件和列表的部分失败、恢复和重试。

## 5. 跨设备验证

覆盖现有及另一台 Android 掌机的内置存储和 SD 卡，同时覆盖直接挂载的 SD 卡。分别记录常见目录、自定义目录、无列表和 RetroArch 实际启动结果。
