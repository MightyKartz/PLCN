## 2. 已连接掌机的情况

| 项目 | 结果 |
|---|---|
| USB 设备 | `Moorechip / QCS_KALAMAP-HDK`，VID `0x18d1`，PID `0x4ee1` |
| `adb devices` | 空 |
| 结论 | 设备处于仅 MTP 模式，未开启 USB 调试 |

- 机型是推断：Moorechip 是 AYN 的公司名，Kalama 是骁龙 8 Gen 2 平台，大概率是 Odin 2 系列。它不是配置中上次使用的 RG476H。
- 用户已确认这台掌机运行 Android；Linux 掌机支持继续暂缓。阶段 5 再次读取 ADB 设备列表仍为空，尚未完成真机调试授权与验证。
- 这种状态下 `list_adb_devices`（`src/retroarch_scanner.py:123`）拿不到任何设备，首页只会显示通用的“未发现可用设备或默认目录”。
- 如果设备运行的是 Linux 系统（ROCKNIX、KNULLI、muOS 等），PLCN 目前没有对应的连接方式，只能拔 SD 卡当本地目录用。

真机验证的前置条件：在掌机上打开“开发者选项 → USB 调试”，并在弹窗中授权这台电脑。

## 3. UI 问题清单

首页和游戏列表本身已经足够简洁，问题集中在旧模型残留和信息密度上。按影响排序：

### U1 路径设置暴露旧配置模型

- 现象：对话框分“设备与目录 / 单项配置 / 批量配置”，要求填写游戏列表路径、系统名称、缩略图保存路径。
- 位置：`src/templates/plcn.html:3029` 起的 `#path-settings`。
- 问题：新流程是“打开游戏库 → 选主机”，这些值都能从游戏库根目录推导。
- 方案：对话框只保留“游戏库目录”和“图片目录（可选覆盖）”；列表路径和系统名称由左侧选择决定，不再让用户填写。

### U2 顶栏“当前列表 / 全部列表”是全局模式切换

- 位置：`src/templates/plcn.html:2623` 的 `.mode-switch`，`switchTab('single' | 'batch')`。
- 问题：它实际只决定批量整理的范围，却占据顶栏最显眼的位置，并且切换后整个工作区语义改变。
- 方案：移入“批量整理”菜单，作为“范围：当前主机 / 全部主机”选项；顶栏去掉这个开关。

### U3 图片目录缺失时逐行重复提示

- 现象：游戏列表每行图片列都显示“未设置目录”，同时“需检查”筛选把全部游戏计入（测试中 22/22）。
- 方案：列表顶部显示一条提示和“指定图片目录”按钮；图片列留空；未设置图片目录时“需检查”不把缺目录算作单个游戏的问题。

### U4 修复预览每行控件过多

- 现象：每行有 1 个勾选框、2 个输入框（游戏名称、封面源英文名）、3 个图标按钮、2 个状态标签，ROM 路径被截断。
- 方案：
  - 名称默认显示为文本，点击后才变成输入框。
  - 3 个图标按钮合并为一个“更换图片”入口，进入单游戏补图窗口。
  - 副标题只显示 ROM 文件名，完整路径放到悬停提示。

### U5 管理入口分散且重叠

- 现象：顶栏“工具”菜单、侧栏“管理”菜单、“任务与恢复”按钮、“PLCN 管理”三标签对话框互相重叠；“路径设置”同时出现在“工具”和“管理”里。
- 方案：合并为一个设置入口，内含“游戏库 / 名称数据库 / 任务与恢复”；侧栏“管理”只保留“打开其他游戏库”。

### U6 首页检测不到设备时缺少引导

- 现象：只有一句“连接 USB 设备并允许调试后，点击‘重新检测’”。
- 方案：
  - 空状态下给出开启 USB 调试的分步说明（可折叠）。
  - 可选增强：识别“USB 已连接但未开调试”的设备并单独提示。这需要在 ADB 之外枚举 USB 设备，三个平台实现不同，单独评估。

### 8.2 交互简化建议

结论：顶栏本身已足够简单，不建议再动。仍然偏复杂的是“批量整理”入口和预览页。按收益排序：

#### R1 “批量整理”菜单改为单个按钮

- 现状：进入预览要四步：点开菜单、选范围、选操作、点“预览变更”（`plcn.html:103` 的 `#organize-menu`）。
- 方案：标题栏直接放“整理本主机”按钮，点击即进入预览，默认同时处理名称和图片。

#### R2 “本次操作”三选一移到预览页

- 现状：菜单里的下拉框有“修复名称并补全图片 / 仅修复名称 / 仅补全图片”三项，需要在看到结果之前选定。
- 方案：预览页顶部放“修改名称”“补全图片”两个勾选框，默认都勾选；取消其一即等同于原来的“仅补图”或“仅改名”。
- 注意：现有逻辑在切换操作类型后会让旧预览失效并重新分析。实施时需确认勾选变化是重新分析还是只过滤已有结果；“仅补图”不重写 `.lpl` 的约定必须保留。

#### R3 “全部主机”改为独立入口并增加汇总确认

- 现状：与“当前主机”放在同一个下拉里，但行为不同：一次确认后自动应用全部列表，不经预览。它是唯一不经预览就写入设备的入口。
- 方案：从菜单中移出，放到左侧主机列表顶部作为独立入口；应用前显示每个主机的变更数量汇总，再确认。
- **待决定**：第 7 节第 3 条已确认阶段 4 沿用“自动应用、不逐项预览”。是否改为“先看汇总再应用”需要重新确认；如果维持原行为，仍建议把入口移出下拉以避免误用。

#### R4 删除右侧检查器

- 现状：在预览中点击任意行会滑出 `#inspector-panel`（`plcn.html:219`），包含“匹配详情 / 元数据 / 文件信息”三个标签、匹配链路和缩略图 URL，并遮住“更换图片”列。
- 问题：其中的名称和图片源编辑与行内编辑、补图窗口重复，其余内容属于调试信息。
- 方案：删除面板及 `src/templates/inspector.js`（215 行）和对应样式；行点击不再触发面板。匹配理由已有悬停提示，如需保留更多信息可放进补图窗口。
- 注意：`preview.js` 的行点击和键盘处理调用 `selectPreviewRow`，删除时要一并处理并更新相关测试。

#### R5 删除预览页顶部流程条

- 现状：`.workflow-strip`（`plcn.html:93`）显示“1. 选择游戏库 已完成 2. 预览变更 已完成 3. 应用变更 等待”。
- 问题：与页面标题“修复预览”和“应用 N 项变更”按钮表达的是同一件事。
- 方案：删除流程条及其状态更新逻辑。

#### R6 游戏列表图片列降噪

- 现状：三类图片全缺时，每行都显示“缺少图片”加“封面 / 游戏截图 / 标题图”三个标签，行高随之变大。
- 方案：全缺时只显示一个“缺图”标记；只有部分缺失或有损坏时才展开三类标签。

#### R7 补图窗口减少手动步骤

- 现状：窗口内有“搜索图库”“预览图片”“搜索备用来源”和本地导入四个入口，另有三段说明文字。

- 注意：候选必须手动选中后才写入、备用图不批量自动应用，这两条约定保持不变。
