# 阶段 1B：扫描配置与状态

本 PR 依赖阶段 1A（PR #10），不修改游戏身份模型或增加多盘写入。

## 界面行为

“更新游戏库”展示主机、默认核心、游戏来源和列表保存位置。游戏来源与列表目标可以位于同一掌机的不同存储空间。现有精确配置、列表路径恢复和唯一主机识别继续沿用；不把 MTP 地址当作 Android 启动路径。

主机、核心、启动路径、官方下载与扫描选项收进“扫描设置与高级选项”。缺少核心路径、本地核心文件不存在或必填高级字段未填时，自动展开并定位。路径存在多个候选或无法识别时仍要求用户核对，不猜测挂载点。

## 核心状态契约

新增 `POST /api/content/core-status`，输入 `root`、`core_path`。只读取本地文件存在性或解析 MTP 地址，不打开 USB 会话，不加载核心。

| state | 显示 | 证据边界 |
| --- | --- | --- |
| unconfigured | 待指定核心路径 | 路径为空或 DETECT |
| available | 核心文件已找到 | 本地文件存在；未验证加载运行 |
| missing | 核心文件未找到 | 指定本地路径不存在 |
| unknown | 安装状态未知 | MTP 无法确认掌机安装状态 |

请求失败明确显示检查失败；下载、传输或填写路径均不冒充安装成功。现有扫描预检仍负责提交边界验证。

## 异步状态约束

- 设备配置读取采用打开代次；关闭或重新打开后，旧结果不能填回。
- 路径识别绑定配置对象、输入修订和请求代次，用户修改后的旧结果不再回填。
- 核心格式绑定当前设备、主机、核心和扩展名；核心文件状态绑定设备、核心与完整路径。
- 点击开始扫描等待最新目录识别完成；目录浏览仍在读取时明确提示等待。
- 新输入清除旧扫描预览；首次自动过滤格式不会误取消并行的目录识别。
