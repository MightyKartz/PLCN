# CHD 原镜像清理工单处置

审查版本 `8fd4b1a`。沿用[原工单编号](FOLLOWUP_TICKETS_77DC98E.md)。本轮只有 R10-01 需要开发处理。

## R10-01 · 最终删除前响应取消，并准确记录改名后的清理结果

**状态：待修复，P1。** 指纹读取成功后能识别改名并保留文件，该场景已通过。剩余两项合并实施和验收。

| 场景 | 已复现的结果 | 修复与验收条件 |
| --- | --- | --- |
| 最终设备查询期间取消 | 从继续清理 API 发起任务，在最后一次路径查询期间取消。查询返回后仍向对象 ID 4 发出删除指令，文件消失，任务报告完成。 | 确认路径和 ID 后，在发送删除指令前检查取消状态。重复该操作，设备删除调用为零，原文件完整，结果反映取消。 |
| 改名使指纹下载中断 | 回读期间将 `data.bin` 改名为 `saved.bin`，设备返回下载错误。首次结果允许重试，再次清理将消失的旧路径计为已删。两次均未发出删除指令。 | 下载失败后核对原路径和 ID。能确认仍为原对象时允许重试；路径消失、身份改变或无法确认时列为待核对。复验时应保留 `saved.bin`，结果给出旧路径和原因，该项不再进入重试或已删清单。 |

首次部署和继续清理共用 [MTP 删除入口](../src/mtp_runtime.py)。在该入口处理取消和身份核对，由[清理结果汇总](../src/chd_deploy.py)沿用已有的取消、可重试和待核对分类。以上两项通过，且普通删除回归通过，即可关闭 R10-01。

## R10-02 · 同名替换 BIN 无法下载时识别身份变化

**处置：验收通过，建议关闭。** 在模拟 MTP 设备上，替换 BIN 的元数据可读，内容无法下载。继续清理对该文件的下载和删除调用均为零。API 返回部分完成，待核对清单仅含该路径一次，可重试清单为空，无继续清理标识。窗口渲染函数显示路径及身份变化原因，并隐藏继续入口。此前暂缓关闭的 R9-01 可同步关闭。

本轮证据来自继续清理 API、模拟 MTP 设备和窗口渲染函数。审查版本通过 675 项 Python 测试和 166 项 Node 测试，未进行真机复测。
