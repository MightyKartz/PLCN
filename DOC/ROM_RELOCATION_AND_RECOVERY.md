# 阶段 4B：目录整理、ZIP 回传与恢复

实施日期：2026-11-16。基于阶段 4A（PR #17）独立提交，未授权自动合并或操作真实掌机。

## 用户流程

1. 打开一台主机列表，在“目录整理与 ROM 压缩”中选择源目录、主机目标目录和电脑工作目录。
2. 分析后勾选平铺候选，点击“预览目录整理”。M3U 仅在盘文件都是源范围内的独立 CHD、至少两张且不重复时可整理；勾选 M3U 会自动包含其盘文件，保留盘序。新建 M3U 仍通过已有多盘检查功能确认分组，不按相似中文名合并。
3. 默认“仅复制到目标”。预览目标、引用范围、空间与电脑备份后确认，完成 SHA-256 回读。原文件、列表和存档保持原状。
4. 在 RetroArch 中用目标文件／ZIP 验证启动、游戏内存档和所需换盘，记录实际核心版本，退出 RetroArch。
5. 改选“复制并更新引用”或“复制、更新引用并清理有备份的原文件”，重新预览。也可从“任务与恢复”的已完成复制记录进入新预览。
6. 只有目标校验、元数据备份、存档规则及引用范围都就绪，才可确认更新。清理前再次核对备份、目标、引用和配置；源文件保留在电脑备份中。

ZIP 路径：先按阶段 4A 生成并验证电脑 ZIP，再从完成结果或 ZIP 任务记录点击“预览 ZIP 回传／替换”。仍有同名 ZIP 的不同游戏必须单独排除冲突后处理，不自动覆盖或合并。旧版 4A 记录缺少目标目录时，ZIP 回传到各原文件所在目录，并在预览中显示准确位置。

“任务与恢复”提供继续与恢复。复制阶段完成后可重新预览切换；已切换或移动的操作若需改变方案，应先恢复或重新分析，不把旧引用方案直接重复提交。

## 支持与例外

| 情况 | 行为 |
| --- | --- |
| 普通独立卡带 ROM、独立 CHD | 保留文件名，复制／更新引用／有备份地清理源文件 |
| CHD 多盘 M3U | 联动盘文件，重建目标 M3U 相对引用，保留盘序及已确认分组 |
| 只移动盘文件，M3U 留在原位 | 更新原 M3U；跨存储时使用经映射的 Android 绝对路径 |
| CUE＋BIN、CCD／TOC／GDI、已有压缩包、软盘或增强资源例外 | 不拆散整理；CUE 仍引用的所选文件阻止执行，未解析描述文件阻止引用切换／清理 |
| 街机 ROM 集 | 沿用 4A 排除，不移动或重新打包 |
| ZIP 格式转换 | 仅使用 4A 已验证副本；再次核对压缩包 SHA-256、唯一成员、解包内容与原 ROM |
| 同名文件／目录、大小写冲突 | 显式阻止，不覆盖、不改名、不按中文名去重 |
| 此前本工具复制出的同一目标 | 仅在完成记录、原来源、源指纹、目标指纹均匹配时复用 |

目录整理使用复制与受控删除，不直接重命名文件。空目录保留以支持原路径恢复；不提供空目录清扫或任意文件名修改。目标目录必须已存在。

## 路径、身份与图片

MTP 地址只用于电脑传输。切换入口前，目标目录必须有唯一的 Android 映射，且反向核对可定位回同一物理目录。不会将 MTP 存储 ID 推测为存储卡卷号；映射未知时仅允许复制。

引用检查覆盖预览列出的递归源目录、目标目录与列表目录，解析 LPL／M3U／CUE，并对未解析描述文件和未知路径提示。范围外引用不声称已穷尽，切换／清理要求用户明确确认范围。

ZIP 的物理文件和 `archive.zip#member.gba` 启动位置分别处理。引用扫描以物理 ZIP 判断消费者，写回时保留成员；恢复时新出现的成员引用也会阻止删除 ZIP。ZIP 文件、内部成员与原 ROM 使用同一主文件名，不借压缩改变保存名称。

路径整理保留 Game／Disc／Content 标识、CRC、人工名称、人工核心与图片选择。ZIP 转换分配新的 Content 标识并延续 Game 与图片选择，CRC 置 DETECT。已确认的 M3U 自身移动会迁移分组键与启动位置，盘成员保留原 Disc／Content 标识；恢复按原关联补丁还原。图片文件命名不变，无需搬移图片。

## 存档检查的明确边界

本项只支持固定全局存档／即时存档目录。原文件名和核心不变，因此不移动或改写存档，不把即时存档当作已验证兼容。

切换前要求：

- 可读取当前游戏库的 `retroarch.cfg`，不含未展开的 include。
- `auto_overrides_enable`、`game_specific_options`，以及六个存档分类／按内容目录保存选项均明确为 false；缺少明确设置也属于待确认。
- `savefile_directory`、`savestate_directory`、`core_options_path` 都是明确、可访问的绝对路径；MTP 须有映射。
- 核心选项文件可读，无未展开的 include 或启用的共享存档选项。
- 受影响列表使用同一明确核心；ZIP 还需属于 4A 的已核对解包支持表。
- 方案执行前与清理前复核配置和目录快照。未知情况阻止切换／清理，允许仅复制。

不自动修改用户 RetroArch 配置，也不猜测未读取的覆盖设置、命令行启动参数或应用私有路径。核心版本与运行报告来自用户，不宣称由 MTP 验证。按内容目录存档、核心覆盖或共享存档的自动迁移不在本项支持范围。

上游核对日期 2026-11-16：[RetroArch 配置项定义](https://github.com/libretro/RetroArch/blob/master/configuration.c)、[全局存档目录说明](https://github.com/libretro/RetroArch/blob/master/retroarch.cfg)、[内容与压缩包加载](https://github.com/libretro/RetroArch/blob/master/tasks/task_content.c)。具体已安装版本仍需用户验收。

## 事务、取消与恢复

复用阶段 3B 的大文件传输和持久备份引擎；整理记录以 `kind=rom_relocation` 区分，在任务页单独显示。

- 服务端保存分析与一次性预览，执行请求仅传预览任务 ID；客户端路径不能替换已审阅方案。
- 输入或游戏库变化使客户端旧预览失效，迟到响应不能重新启用确认。SSE 断线保留操作锁，不重复提交。
- 原文件和目标输出先建立校验过的电脑备份；变更前复核源、目标、配置、引用快照和关联键。
- M3U 新文本作为受控输出备份，原 M3U 留存至引用更新完成。引用清理检查识别本操作新建的描述文件，防止将自己的输出误判为外部变化。
- 更新列表与关联使用已有元数据事务；恢复不能从嵌套元数据记录绕过源文件恢复。
- 清理只针对已确认且不再被范围内其他消费者引用的源文件，受符号链接或外部内容变化影响时停止。
- 取消或断连保存逐文件状态；继续时复核已完成上传及备份，只清理余下源文件。
- 恢复顺序为原文件 → 引用及关联 → 本操作独占的新输出。外部修改的文件不覆盖；原目录保留，恢复可还原相对路径关系。
- 新引用会沿 M3U 的盘文件传递：若新的列表使用了整理后的 M3U，恢复时保留 M3U 与它所需的全部输出；不把内部引用误当作独立外部消费者而永远无法清理。
- 本次文件净释放量按实际逐文件结果统计，不含电脑与元数据备份。先复制、后移动是两个独立操作，不能把第二次操作的净释放当作整套流程的总节省。

API：`/api/rom-storage/relocation/{preview,apply,recover}`。记录仍位于应用数据目录 `chd-deployments/<id>/manifest.json`，避免再建一套相互独立的恢复引擎；UI 将 CHD 与目录／ZIP 操作分开显示。
