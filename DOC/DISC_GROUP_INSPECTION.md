# 阶段 2A：游戏组、多盘详情与引用检查

实施日期：2026-11-16。依赖阶段 1C，不执行阶段 2B 的 M3U 创建／修改、盘序写回、存档迁移或恢复。

## 用户入口与范围

选择 Saturn／PlayStation 列表后，游戏列表工具栏提供“多盘与引用检查”。弹窗是一份独立的只读分组视图：先看分组、光盘、关联文件和原始入口数量，再展开各组查看顺序、原入口与文件引用。支持名称／路径搜索、问题提醒／已有 M3U／候选组筛选和分批显示。

已有列表浏览与写回契约保留。侧栏数字仍按原有入口口径；新的分组视图不冒充已经合并掌机列表。检查直接读取原始列表，包含普通浏览视图可能隐藏的伴随条目，不能靠普通视图的同名归并结果决定实际引用。

原列表、光盘、音轨、核心与图片选择不写入；可按阶段 1A 规则补充电脑本地的标识索引。读取图片选择只复用已有记录，不触发名称匹配或图库查询。

## 分组依据

- 平台限 Saturn／PlayStation，兼容现有 SS／PS1 名称。
- 文件名中的明确盘号支持 `(Disc 1)`、`Disc1`、`Disc 1`、`Disk`、`CD`、方括号及 `of N` 标记；1～99 之外或多个盘号标记留待核对。
- 候选组要求同一目录、同一文件名家族及相同地区／版本标签。中文显示名不作为合并依据；不同目录、地区、修订、汉化标记保持独立。
- 沿用已记录的精确简称映射（例如 GulliverBoy → Kuusou Kagaku Sekai Gulliver Boy）。不使用模糊译名或通用 CN 字符清理来证明同版。
- 附赠、试玩、特典、Soundtrack 等标记的盘保持独立并提示。系列续作不凭相似标题归组。
- 已有 M3U 按实际声明建立组，保留引用顺序；相同名字但未被引用的文件不能因此归入该 M3U。
- CUE 的 FILE 引用作为音轨／组成文件。原列表即使同时声明 CUE 和 BIN，统计也区分光盘与关联文件。

分组只是候选投影，不新增持久游戏组、不重分配既有 UUID，也不暗示文件已经被合并。阶段 2B 将基于用户确认的操作方案处理入口与身份衔接。

## 文件与引用图

新增 `GET /api/playlist/discs?path=<当前列表>&system=<平台>`，沿用本地服务的认证与同源限制。

响应包括：

- `groups`：`id`、`kind`、`status`、成员／光盘／关联文件 ID、原列表索引、分组依据、问题和总盘数是否明确。
- `files`：检查图节点 ID、原路径、格式、存在性、体积、列表反向引用、描述文件反向引用和盘号证据。
- `references`：M3U／CUE 的源节点、目标节点、原始行号。
- `entries`：原入口索引、原启动路径、Game／Disc／Content UUID、原标签、核心以及已保存图片源。
- `coverage`：已读列表目录与数量、读取失败、是否递归；`summary` 按当前组统计，覆盖范围另记录全图文件数。

图节点／组 ID 用于检查结果定位，不是新的持久游戏身份。同一物理文件通过多种已保存路径映射汇合时，各入口的原启动路径和 UUID 全部保留；节点列出 `content_ids`。多绑定不强选一个 `content_id`，并显示路径别名提醒。

检查当前列表同级的全部 `.lpl`，包括其他主机列表对同一文件的引用。只覆盖已展示目录，不递归其他列表目录，更不宣称掌机全盘已无其他引用。其他列表损坏或不可读时明确列出错误；后续替换／清理必须将覆盖不全视为未满足条件。

## 路径与读取边界

本地路径只查询文件元数据；只读取 M3U／CUE 的小型 UTF-8（兼容 BOM）描述内容，不全量读取 CHD／BIN／ISO，也不解压 ROM。描述文件超过 1 MiB、非 UTF-8、无效语法、空引用或网络地址均显示待处理问题。

MTP 仅使用当前游戏库已保存扫描配置的 Android 目录 → 传输目录映射。优先精确的最长前缀；同前缀存在多个不同目标时显示未知，不猜挂载点。ROM 可来自同一掌机的另一存储。引用其他物理设备不自动接入。目录元数据在一次检查内复用，避免逐文件反复枚举相同 MTP 目录。

状态明确区分 `present`、`missing`、`unmapped`、`unreadable`、`invalid`、`unchecked`。映射不明、压缩包成员未检查或读取失败不能升级为“缺失”。本轮检查只支持本地与 MTP，ADB 连接明确提示改用文件传输。

只解析 M3U／CUE 内部引用；CCD／TOC／GDI 的文件存在性可显示，但内部引用标记尚未检查。嵌套 M3U 可建立图并保持展开顺序，同时提示核心兼容性未确认；循环引用会被报告，不进入无限读取。此处不新增对嵌套 M3U 的运行兼容承诺。

## 问题与证据边界

报告已知盘号缺口、重复盘号、声明总数冲突、失效文件、不同版本标记、不同游戏名称、特殊盘、循环、重复／非法引用、单项核心不同、共享文件和路径别名。版本问题列出相关路径，便于核对。

未标记的汉化／修订差异不能仅靠文件名鉴别；同名文件不是二进制等价证明。未声明总盘数时不能证明尾部完整。M3U 引用顺序只是现有声明，不代表核心已成功加载或完成真机换盘。检查结果不授权清理文件。

本轮完整回归 329 项通过（含真实服务浏览器流程）；新增 Node 状态行为 5 项通过；JavaScript 检查通过（13 个脚本、80 个事件处理器）。

Node 状态检查覆盖关闭后重开、旧请求不能回填／解锁新检查、错误后可重试、搜索／筛选及未知状态不误报丢失。真实服务浏览器样例检查浅色 1440×900、深色 1100×700 布局，展开顺序、候选组搜索和原列表字节不变。样例镜像为占位文件，不是实际核心加载证据。

本轮未重启日常 7777 服务，未连接或写入掌机。MTP 测试为受控边界样例，真实双存储读取与换盘留待真机验收。下一项阶段 2B：M3U 预览／应用／恢复、盘序编辑、存档衔接与身份关联迁移。
