## R10-01 · 指纹回读期间改名，继续清理会删除新位置的文件

**复现与影响**　在临时游戏库中生成待清理的 `data.bin`。从公开 API 启动继续清理，设备层解析出对象 ID `4`。在读取该文件计算指纹期间，在设备侧将它改名为 `saved.bin`，保持对象 ID 和字节不变。当前实现随后仍向 ID `4` 发出删除命令。磁盘上的 `saved.bin` 消失，任务结果却报告 `data.bin` 已成功删除。

**涉及调用方与修复建议**　首次部署和继续清理均经过同一 MTP 删除入口。保留回读前的身份检查；指纹校验结束、即将调用设备删除函数时，再检查取消状态，并按原获准路径重新查询对象 ID。路径已消失、指向其他对象或无法确认时，停止本项删除并返回待核对路径和原因。避免把改名记作本次删除成功。[MTP 删除入口](../src/mtp_runtime.py) · [文件操作边界](../src/chd_io.py) · [部署与继续清理](../src/chd_deploy.py)

**验收**

- [ ] 复现 `data.bin → saved.bin` 的时序。设备删除记录中没有针对 ID `4` 的本次调用；`saved.bin` 字节完整。API 的已删清单不含 `data.bin`，窗口可查看待核对路径及原因。
- [ ] 将回读期间的变更分别换成“原路径出现不同 ID 的对象”和“用户取消”。在发出设备删除指令前停止，分别报告身份变化或取消；原对象、新对象及之前已完成项的结果均可核实。
- [ ] 对照路径、对象 ID、指纹和引用均保持有效的情况，正常删除和删除后的回读校验仍通过。[设备层测试](../tests/python/test_mtp_runtime.py) · [部署测试](../tests/python/test_chd_deploy.py)

## R10-02 · 新 BIN 的元数据可读、内容无法下载时，身份变化未进入待核对清单

**复现与影响**　让原 BIN 首次清理失败并取得继续标识。将原路径换成 ID 和内容均不同的新 BIN；使设备仍能列出其新 ID，但下载该 BIN 时返回读取错误。继续清理在范围校验中提前失败，API 恢复旧清理方案，窗口拿不到身份变化明细。新文件仍完整，但用户无法从此次结果判断它为何应被保留。

**涉及调用方与修复建议**　范围校验和逐文件清理目前用完整指纹判断路径是否缺席，导致身份分流前就尝试下载替换件。对 MTP 路径，仅判断存在性或身份时使用设备元数据；身份明确变化时将路径列入 `unverified`。对仍获准清理的文件保留指纹校验，对引用文档保留内容校验；元数据查询本身出错时也不能据此判定路径缺席。[范围校验及清理循环](../src/chd_deploy.py) · [设备元数据与指纹读取](../src/chd_io.py) · [任务结果传递](../src/api_chd.py)

**验收**

- [ ] 从公开 API 复现“元数据可读，替换 BIN 下载失败”，记录下载和删除调用。窗口与 API 均显示该 BIN 的路径及身份变化原因；替换 BIN 无需下载，也未收到删除命令。
- [ ] 仅剩该 BIN 时，结果为部分完成，该路径在 `unverified` 中只出现一次，`remaining` 为空，不签发 `cleanup_id`。若仍有其他可重试的获准文件，后续方案只包含那些文件，并保留该 BIN 的待核对明细。
- [ ] 同一对象内容被修改时，指纹校验仍阻止删除；新增引用时，范围校验仍保护被引用文件。正常源文件可读时继续清理成功。[部署回归测试](../tests/python/test_chd_deploy.py)
