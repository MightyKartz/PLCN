# 阶段 4A：目录建议与卡带 ZIP 电脑副本

实施日期：2026-11-16。基于阶段 3B 分支单独提交 PR，暂不合并。

## 本项交付

主界面将原“存储优化”标为“光盘 CHD 转换”，新增“目录整理与 ROM 压缩”。选择当前主机列表、游戏源目录和已存在的主机目标目录，递归分析源目录。目标默认为源目录，可另选。本地使用目录选择器；MTP 在同一物理设备的本机／存储卡间浏览，不要求输入 Android 启动路径。

目录结果明确区分：可平铺候选、已经平铺、同名冲突、保留目录例外。独立 CHD 与普通卡带文件进入建议；CUE、多文件描述符、M3U、已有压缩包等保留原结构。同名判断包含源目录内重名与目标目录已有文件／文件夹，大小写不敏感；不覆盖、不按中文名合并、不自动改名。

候选表示需要下一项继续核对的目录建议，不是可直接执行的移动方案。当前检查不宣称已穷尽跨列表引用、验证 CHD 内容或完成存档迁移。

ZIP 转换只生成电脑副本：

1. 当前列表中所有直接关联该源文件的核心都必须属于已核对的解包支持表。
2. 复制源 ROM 到电脑工作空间，比对分析时记录的 SHA-256。
3. 使用标准 ZIP DEFLATE，每包仅有原文件名的一个成员。ZIP 与内部 ROM 的主文件名一致，避免引入新的存档名称差异。
4. 重新打开 ZIP，以有界内存逐字节比对解压内容与源副本，并再次核对源文件 SHA-256。
5. 校验完成才发布输出，记录 ZIP 指纹、源指纹、成员名、转换前后大小和来源核心。

按源路径区分输出子目录保存 ZIP，同名游戏可各自生成副本，不会互相覆盖。压缩后可能变大，如实报告大小；设备原文件仍保留，因此掌机实际节省空间固定为 0，不把潜在节省当成已释放空间。

## 格式与上游依据

查阅日期 2026-11-16；以下是上游代码声明，**不证明设备上安装的核心版本及当前 RetroArch 构建已支持 ZIP**。加载和存档仍需后续验收。

| 核心 | 本项允许的原格式 | 上游依据 |
| --- | --- | --- |
| mGBA | GBA、GB、GBC（与所选主机匹配） | [retro_get_system_info](https://github.com/mgba-emu/mgba/blob/master/src/platform/libretro/libretro.c)：need_fullpath=false、block_extract=false |
| Gambatte | GB、GBC | [retro_get_system_info](https://github.com/libretro/gambatte-libretro/blob/master/libgambatte/libretro/libretro.cpp)：need_fullpath=false、block_extract=false |
| Snes9x | SFC、SMC | [retro_get_system_info](https://github.com/libretro/snes9x/blob/master/libretro/libretro.cpp)：need_fullpath=false、block_extract=false |

[RetroArch 内容加载实现](https://github.com/libretro/RetroArch/blob/master/tasks/task_content.c)根据核心的 block_extract 等条件处理压缩内容。ZIP 扩展名未出现在核心 info 的原始内容扩展名中，不能据此直接认定不支持；同样不能因扫描器接受 ZIP 就认定所有核心都支持。

NES／MD 可提供普通文件的目录建议，但当前核心解包支持不在本项核对表，不转换 ZIP。街机 ROM 集完全排除；光盘 ZIP、软盘、7z／RAR 重新打包以及系统子模式不在范围内。同文件名关联的 IPS／BPS／UPS 补丁、MSU／PCM 增强资源会阻止该 ROM 的 ZIP 转换并提示保留目录。未知或非当前列表的 ROM 不推测核心。

## 状态与执行契约

- `POST /api/rom-storage/analyze`：后台只读分析，服务端保存方案。
- `POST /api/rom-storage/convert`：只接受分析任务 ID 与所选文件 ID，使用服务端方案；忽略客户端额外提交的路径。
- 无效选择不消费方案；有效提交一次即消费，重复点击不会重复执行。
- 配置、列表、目录变化使旧方案失效；异步目录响应按请求版本核对，不允许旧存储响应覆盖新选择。目录浏览中点击分析会使用当前已读目录，无需额外点击“使用此目录”。
- SSE 断线保持操作锁并重连；不再次提交任务。取消在流式读取／写入边界检查，未验证的工作目录清理，已验证结果保留。
- 工作空间预算为所选源大小的三倍加 64 MiB，覆盖源副本、ZIP 最坏扩张及余量；执行前重查空间。
- 记录保存在应用数据目录 `rom-storage/<id>/manifest.json`，设置 → 任务与恢复可查看完成、失败、取消及进程中断状态。
- 进程中断可能留下未发布工作文件；本项不自动续传或清理未知输出，记录含源方案和确定的输出根目录，供核对。需要重新分析以生成新的副本任务。
- 本项不调用 MTP 上传、源删除或元数据写回，不改变 Game／Disc／Content 标识、名称、图片选择、人工核心或存档。

## 验证

自动验证覆盖 ZIP 实际解包、中文文件名、不同目录同名游戏、未知／多核心限制、伴随文件与多文件例外、源和列表变化、空间不足、取消、损坏解压、服务端一次性方案，以及模拟的双存储 MTP 只读下载。浏览器使用独立临时 HTTP 服务与合成库验证目录选择、冲突展示、ZIP 生成、持久任务记录、浅深主题和 1440×900／1100×700 两种窗口。

本地全量检查 401 项通过，新增 ROM 状态检查 7 项通过；JavaScript 语法与 Python 编译检查通过。截图保存在 `output/playwright/browser-smoke/{1440x900,1100x700}/11-rom-*.png`。

不重启日常 7777 服务。真机核心加载、存档连续性和压缩包扫描行为待用户稍后验收。

## 阶段 4B 后续边界

目录移动／替换需复用阶段 3B 的已确认方案、备份与恢复机制，并补齐：

- M3U 自身移动后重建相对引用，更新所有已声明范围内的 LPL／M3U；CUE＋BIN 保留目录关系。
- 路径移动保留 Content 标识；格式转换建立新 Content 标识并延续 Game／Disc／图片关联。
- 检查存档目录、按内容目录分类选项和覆盖配置；未知时不推测存档位置。
- 区分 ZIP 物理文件与 `zip#member` 启动引用，核对文件名／成员名及保存名称。
- 同名冲突由预览排除或用户单独处理；不覆盖或自动去重。
- 真机运行报告和引用范围明确后才能切换引用；完整备份、回读与引用校验后才能清理源文件。
- 恢复还原原目录关系、引用、身份与存档；新出现引用的输出不得自动移除。
